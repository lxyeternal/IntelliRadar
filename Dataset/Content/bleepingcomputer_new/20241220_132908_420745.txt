Named Graboid, after the sandworm in the 1990 movie "Tremors," the malware spreads to systems with an unsecured Docker engine.

Docker containers are environments isolated from the operating system with code and dependencies needed by an application to run the same on any supported infrastructure.

Searching on Shodan search engine, researchers from Palo Alto Networks found more than 2,000 insecure Docker services exposed to the public web. This is fodder for Graboid.

In their analysis, the researchers discovered a script from Graboid's command and control (C2) server that retrieved a list with more than 2,000 IP addresses, suggesting that the attacker already scanned for vulnerable hosts.

It is unclear how many of them were infected since the malware picks the next targets at random from the list.

After compromising one of them, the attacker sends remote commands to download the "pocosow/centos" Docker image from Docker Hub and deploys it.

The image has the Docker client that is used to communicate with other Docker hosts. The cryptomining activity (Monero) is carried through a separate container called 'gakeaws/nginx,' which poses as the nginx web server.

'pocosow/centos' is also used to download from the C2 a set of four scripts and execute them:

live.sh​ - sends info on CPUs available on the compromised host
	worm.sh - downloads the list of vulnerable hosts, picks new targets and deploys 'pocosow/centos' on them via the Docker client
	cleanxmr.sh - stops cryptomining activity on a random host
	xmr.sh - selects a random address from the list of vulnerable hosts and deploys the cryptomining container 'gakeaws/nginx'
Palo Alto Networks discovered that Graboid receives commands from 15 compromised hosts, 14 of them being present in the list of vulnerable IPs and the last one having more than 50 known vulnerabilities, a clear indication that the attacker compromised them specifically for malware control purposes.

The two containers involved in the Graboid cryptojacking operation have been downloaded thousands of times. The CenOS masquerader has over 10,000 pulls while the nginx poser has about 6,500.



Graboid constantly queries the C2 server for new vulnerable hosts and uses the Docker client tool to remotely download and deploy the infected container.

Apparent random activity

Apparent random activity

Graboid follows a pattern that may seem inconstant and the reason for this remains unclear. Theories like bad design, evasion, or sustainability are all plausible explanations, the researchers say in a report today.

Each miner is active around 60% of the time and mining is limited to 250 seconds per session. Furthermore, miners don't work at the same time and don't even start the moment they're installed.


"It randomly picks three targets at each iteration. It installs the worm on the first target, stops the miner on the second target, and starts the miner on the third target. This procedure leads to a very random mining behavior" - Palo Alto Networks


Simply put, compromised hosts in the botnet control the mining process on other infected hosts by instructing them to start or stop the session.

In a simulation of the worm activity, the researchers determined that Graboid needs about an hour to spread to 1,400 compromised Docker hosts. If each of them had one CPU, the botnet would have a 900 CPU mining power at all times.

Cryptojacking campaigns involving Docker containers have been reported in the past. A report in November last year from Juniper Networks revealed that cybercriminals were taking advantage of misconfigured Docker services to add containers with a Monero mining script.

Dofloo trojan, a botnet known for launching DDoS attacks and cryptomining activity, over the summer targeted misconfigured APIs of the Docker Engine-Community DevOps utility.
