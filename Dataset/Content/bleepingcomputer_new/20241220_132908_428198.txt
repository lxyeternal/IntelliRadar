
	   


Researchers found a way to bypass a patch Microsoft released to address a bug in the Windows printing services, which gives attackers a path to executing malicious code with elevated privileges.

Tracked as CVE-2020-1048, the initial flaw received an initial fix in May and another one is coming with this month’s rollout of security updates from Microsoft.

New patch on the way

Discovered and reported responsibly by Peleg Hadar and Tomer Bar of SafeBreach Labs, CVE-2020-1048 affects Windows Print Spooler, the service that manages the printing process.

A fix will become available on August 11.

Technical details for the new bug are still private but will be published after the release of the patch, along with a proof-of-concept Mini-Filter driver that shows how to prevent in real time the exploitation of the two vulnerabilities.

Planting malware

Exploiting CVE-2020-1048 is possible by crafting malicious files parsed by the spooler. One type is .SHD (Shadow) format and contains metadata for the print job, like SID - the ID of the user creating the job. The other is SPL (Spool file), with the data that needs to be printed.



“This seemed very interesting, as it provides a convenient way to send data directly to the spooler, which will (probably) be parsed and be used by other components as well,” the researchers write in a technical report today.

By dissecting the printing process and understanding how it all works, the researchers discovered that a function called ProcessShadowJobs processes all the SHD files in the spooler folder when the process starts.

Knowing that Windows Print Spooler runs with SYSTEM privileges and any user can drop SHD files into its folder, the researchers tried to find a way to write to the system32 directory, a task that requires elevated privileges.

Hadar and Bar discovered that they could modify an SHD file to include the SYSTEM SID, add it to the Spooler’s folder, and restart the computer for the Spooler to perform the task with the rights of the most privileged account on Windows.

Along with an arbitrary DLL (wbemcomn.dll) cloaked as an SPL file, they copied the malcrafted SHD to the spooler’s folder. A reboot later, they achieved privilege escalation and wrote their DLL to the System32 folder.



“As a bonus, multiple Windows services loaded our DLL (wbemcomn.dll) as they didn’t verify the signature and tried to load the DLL from an unexisting path, meaning we also got code execution” the two researchers said.

This exploitation method no longer works on updated systems but Safebreach researchers discovered that they could bypass Microsoft’s patch and achieve similar results.

While neither of the issues allows an adversary to compromise a host, they can serve in the second stage of an attack and lead to a full system take over.

Hadar and Bar will present their findings on Thursday at the Black Hat USA security conference.
