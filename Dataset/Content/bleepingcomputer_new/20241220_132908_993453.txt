
	   


Researchers are warning about a hacking technique that enables attacks on the local network using JavaScript on a public website. Using the victim's browser as a proxy, the code can reach internal hosts and do reconnaissance activity or even compromise vulnerable services.

The method is not fully obstructed by the same-origin policy (SOP), the web app security model that restricts interaction between pages of different origin, and it can bypass firewalls because the browser can access the localhost and the local network.

Security researchers at Forcepoint, a company where one of the partners is the U.S. defense contractor Raytheon, admit that the technique is not new and that the security community is aware of it. However, scant resources on the topic and the underrated attack surface make it worthy of attention.

The technique takes advantage of how the SOP typically functions in a browser, allowing cross-origin embedding and writing between two different origins and blocking reading the response.

In a typical scenario, this means that it is possible to send cross-domain requests but the JavaScript code cannot read the response. The result is one-way access to the local network.

However, JavaScript errors can provide valuable information in a reconnaissance stage, while exploitation of some devices on the network may be possible via cross-site request forgery (CSRF) vulnerabilities, which are common in home routers.

The researchers say that an attacker can use a malicious JavaScript on a public website to at least "discover internal hosts, do limited port scanning, do service fingerprinting."

Among the attack possibilities, Forcepoint lists taking over a victim's router by changing the access password or its configuration or compromising vulnerable devices in an organization.

Deanonymizing TOR users with the browser configured insecurely would also be possible where communication with the LAN is allowed. Using CSRF the router could ping an external host to show the real IP address of the TOR user.

An attacker can turn to JavaScript to find out the internal IP address of the victim, and then make educated guesses about the IP of other hosts on the network.



Running port scans on the potential hosts is a good way to check the accuracy of the speculation. This will also reveal any open ports and the services available, useful details for planning an attack.

Because of the SOP, JavaScript cannot read the response of a direct HTTP connection to the hosts. But by loading an image from the HTTP port of the host a "onerror" or "onload" event may occur, indicating that the port may be open; a timeout means that the port is closed. This approach is prone to false positives.

"Knowing the local IP address and filling it out with educated guesses of hosts, we can make a malicious page that portscans these hosts, similar to some open-source tools available. The HTML file with our embedded port scanning JavaScript is placed on some other domain, which will be a publicly available server in the general case," the researchers explain.



With a list of potentially open ports, the attacker can find out the services that use them. A non-direct method is again the key.

Because of the SOP restrictions, the JavaScript cannot read from the page, but it can make a determination by using service-specific default images to trigger "onerror" and "onload" events that show if they are present on the host.



The information obtained this way can then be used to prepare an attack with clear targets. Depending on the target, the researchers say that it may be possible to browse the victim's internal network from the public internet.

One example refers to a target website vulnerable to cross-site scripting (XSS), configured to communicate with an intranet page. Running malicious JavaScript on the faulty website would allow the attacker on the local network.



Starting from the initial reconnaissance scenario, which does not involve a vulnerability, an attacker can adapt their tactic for a successful mission. Learning about services enables the threat actor to get familiar with the software and discover a way to slip in undetected.

Defending against these tactics would be surfing through a web proxy. If this is not an option, detecting external JavaScript trying to connect to a private IP address is the next best thing.


"It should be considered suspicious behavior if a web page fetched from the public Internet attempts to access a non-routable IP address, such as localhost or the internal network. Through our telemetry we have not seen benign web pages that reside on the public Internet that would have a valid need for connecting to a private IP address, nor have we been able to identify any valid and reasonable business use-case for doing such a thing. It is questionable whether it should be necessary to allow connections to private IP addresses from web pages that are located on the public Internet other than potentially in some edge cases."
