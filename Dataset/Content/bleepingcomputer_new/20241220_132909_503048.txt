
	   


A weakness in the protection of messages delivered using the Telegram Bot API gave researchers access to the communication flow between a piece of malware and its operator.

Dubbed GoodSender by its author, the threat is a simple .NET program that used Telegram network to send its operator information collected from the compromised host; this enabled the handler to connect to the victim's host remotely.

Not all Telegram messages have the same protection

While analyzing GoodSender, malware researchers at Forcepoint (joint venture of Raytheon Company and Vista Equity Partners) discovered that the Telegram Bot API uses a weaker level of protection for the messages.

As TLS alone is not enough to ensure robust encryption by today's secure communication standards, it is used in conjunction with additional encryption protocols, like Telegram does with MTProto or Signal with the Signal protocol.

According to the experts, the bot API token and a randomly generated chat ID are all someone in a man-in-the-middle position needs to accomplish just that. The former piece of information is present in the programs using the Telegram Bot API and in messages, while the latter is sent in Bot API requests.

"To make matters worse any adversary capable of gaining a few key pieces of information transmitted in every message can not only snoop on messages in transit but can recover the full messaging history of the target bot," Forcepoint writes in a report shared with BleepingComputer.

Getting the entire chat log is possible with the 'forwardMessage()' method that can send to any user the messages a bot has access to. Messages come with incremental IDs starting from zero; this permits identifying all messages in a group and forwarding them to an arbitrary user.

Telegram bots can be used for a variety of things, from enabling integration with other services, accepting payments from other Telegram users, to creating alerts and connecting people based on common interests or proximity.

Forcepoint has informed Telegram of the issue and recommends users to avoid using Telegram bots and channels/groups with a bot.

Malware author has terrible opsec skills

GoodSender works by enabling a remote desktop connection to the infected machine. It does this by creating an admin user on the system and enabling the remote desktop feature, ensuring that it is not blocked by the firewall.

The Telegram channel is then used to send the victim host IP address, the admin username and password to the operator.


GoodSender delivering IP, username and password to Telgram C2

The way Telegram Bot API works allowed the researchers to forward GoodSender communication to their Telegram profile and discover details about its activity.



Furthermore, the fact that the malware author failed to separate the development/testing and operational environments helped Forcepoint track the activity to its early stages.

One of the test machines belonged to the malware creator, and the researchers were able to see the IP address along with personal details, including their Telegram account.

It appears that the Telegram bot initially served a different piece of malware, called RTLBot, and the infrastructure was initially hosted on the malware author's personal computer. On February 20, the author moves it into Amazon Web Services (AWS). GodSender became active on April 1st.

EternalBlue may be used to get to victims

The researchers at Forcepoint cannot say without a doubt what is the distribution method for GoodSender, but the fact that the actor "makes heavy use of the free EternalBlue vulnerability scanner" is an important clue. EternalBlue was used in the WannaCry ransomware attack in 2017.

Telemetry data shows that at least 120 systems were infected with GoodSender. Most of them are in the US and Vietnam, but Forcepoint saw infections in other parts of the world as well.



Update: A previous version of the article presented the research from Forcepoint in a way that may have confused some readers. We have updated the article to make it more clear. Particularly, messages sent by Telegram bots benefit from weaker protection compared to user-to-user messages; this could be leveraged by a threat actor intercepting HTTPS traffic to get the bot API token.
