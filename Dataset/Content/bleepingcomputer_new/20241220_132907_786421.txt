
	   


A new critical vulnerability in the Exim mail transfer agent (MTA) software was patched to prevent denial of service (DoS) or possibly remote code execution attacks.

The security flaw tracked as CVE-2019-16928 and reported by QAX-A-TEAM has been fixed in Exim version 4.92.3, also released today, and it impacts all versions 4.92 up to (and including) 4.92.2.

"There is a heap-based buffer overflow in string_vformat (string.c). The currently known exploit uses a extraordinary long EHLO string to crash the Exim process that is receiving the message," says the security advisory.

There is no other known mitigation for this security flaw according to the security advisory besides updating all vulnerable Exim servers.

This is the second critical Exim flaw patched this month after another bug—tracked as CVE-2019-15846—affecting versions 4.80 up to and including 4.92.1 made it possible for potential local or unauthenticated remote attackers to execute programs with root privileges on servers that accept TLS connections.

Servers exposed to attacks

According to a mail server survey published by E-Soft Inc, Exim is currently the most used MX server being installed on more than 57% out of a total of 1,740,809 mail servers reachable on the Internet, representing just over 507,000 Exim servers.

However, a Shodan report estimates the number of servers at roughly 5 million, with more than 3,300,000 using Exim 4.92, over 46,000 running 4.92.1, and roughly 166,000 with 4.92.2.

What's important is that hundreds of thousands—if not millions of servers—are currently exposed to denial of service (possibly to remote code execution) and remote command execution attacks if not urgently patched against CVE-2019-16928 and CVE-2019-15846.



Previous Exim attacks

A flaw tracked as CVE-2019-13917 was patched in July with the release of 4.92.1, a vulnerability that would allow local or remote attackers to execute programs with root privileges on servers with unusual configurations.

Another security issue tracked as CVE-2019-10149 discovered in early June makes it possible for hackers to remotely exploit MX servers running Exim 4.87 to 4.91 for certain non-default configurations, while local attackers would be able to exploit all servers.

One week later, attackers started scanning for and attacking vulnerable Exim servers gaining permanent root access via SSH, right after around 70% of all Exim servers were patched against the CVE-2019-10149 flaw, as discovered by RiskIQ Leading Threat Researcher Yonathan Klijnsma


CVE-2019-10149 patch timeline (RiskIQ)

Microsoft also issued an alert regarding a Linux worm on June 17, a malware strain that was actively targeting Azure Linux VMs running vulnerable Exim versions.

"If you can't install the above versions, ask your package maintainer for a version containing the backported fix," Exim's security team also says in the advisory released today.

"On request and depending on our resources we will support you in backporting the fix. (Please note, the Exim project officially doesn't support versions prior the current stable version.)"
