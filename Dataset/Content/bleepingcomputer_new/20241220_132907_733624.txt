
	   


Mozilla patched a vulnerability in the Firefox web browser with the launch of the 68.0.2 release which would allow unauthorized users to copy passwords from the browser's built-in Save Logins database even when protected with a master password.

"Stored passwords in 'Saved Logins' can be copied without master password entry" according to Mozilla security advisory, which also rates the security flaw tracked as CVE-2019-11733 as having a 'moderate' impact.

The flaw allows anyone with local access to a computer running an unpatched version of Firefox to go to the Save Logins dialog available in Firefox's Options > Privacy & Security preferences menu and copy the password stored for any of the saved logins by right-clicking and choosing the "Copy Password" option.

Firefox logins and passwords

Exposing saved logins to unauthorized access

"When a master password is set, it is required to be entered before stored passwords can be accessed in the 'Saved Logins' dialog," says Mozilla.

"It was found that locally stored passwords can be copied to the clipboard through the 'copy password' context menu item without first entering the master password, allowing for potential theft of stored passwords."

This happens even though the browser will ask for the master pass, which is the method used by Firefox to enabled users to secure their saved logins from unauthorized access.

Mozilla's Firefox 68.0.2 security patch fixes this vulnerability, which means that third parties with local access to a Firefox user's computer will no longer be able to steal their passwords if a master password is set. 


Copying a password

Turned on by default without a master password

However, and this is an important side note, Firefox's password manager is turned on by default to allow users to save their logins.

While this is a really good idea given that most people go for the highly dangerous route of reusing passwords, the downside is that Firefox will not also ask its users to also set up a master password to protect their saved credentials.

Thus, it will expose their passwords to anyone with physical access to their computers exposing highly sensitive information to local attackers via the browser's default configuration.

The good news is that the benefits of this approach outweigh its drawbacks given that the chance of someone gaining local access to one's computer is a lot smaller than of an attacker taking over a user's accounts because of previously leaked and reused passwords on other online platforms.

Another thing worth mentioning is that Firefox comes with an auto-update feature that will make sure that all users have their browser's automatically patched when new versions with fixes for security flaws are released by Mozilla.


Firefox auto-update

To enable auto-updates one has to go to the General preferences screen and search for Firefox Updates where Firefox can be allowed to automatically install for updates—Mozilla's recommended option—or set to check for updates and let the users choose to install them.

While this is the way to go if one wants to automatically receive the latest Firefox security updates, this might also backfire if one of the future updates also include a bug like the one that disabled all addons for users who updated to version 66.0.3 on May 3rd.

The issue was caused by Mozilla allowing an intermediate certificate used to sign Firefox addons to expire. Seeing that Firefox requires addons to be signed by a valid certificate, users suddenly noticed that all of their addons were disabled once the certificate expired.

Mozilla also fixed a couple of actively exploited zero-days, a remote code execution and a sandbox escape, in the 67.0.3 and 67.0.4 versions, later discovered to have been used as part of a chained attack targeting Coinbase and other cryptocurrency firms, with the end goal of gaining access to their networks.
