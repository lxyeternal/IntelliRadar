
	   


Threat actors ran a malvertising campaign on the Russian Yandex.Direct advertising network starting October 2018 to disseminate a malware cocktail designed to encrypt victims' data and steal cryptocurrency.

The hacking group targeted Russian organizations using malicious payloads camouflaged as document templates and hosted on the GitHub code hosting platform, one of the goals being to steal sensitive cryptocurrency-related data.

As the ESET Research team detailed in its report, Yandex disabled the malvertising campaign after receiving their alert about malicious ads used to redirect victims to malware-ridden template packs.

ESET Research's analysis further revealed that the targets were lured to the malvertising landing pages after searching for key-phrases similar to "download invoice template," "claim complaint example," or "examples of legal contracts" which indicates that the campaign was targeting corporate entities by attempting to compromise their accountants' computers.

The researchers also found that "the cybercriminals put the malicious files on their GitHub repository only for a limited period of time, probably while the ad campaign was active. Most of the time, the payload on GitHub was an empty zip file or a clean executable."

Coupled with the fact that the payloads were distributed using GitHub, this added to their landing pages' not raising any question marks from targets redirected via Yandex search queries.


Malvertising landing page

Payloads, data collection, and exfiltration

The malicious actors used two GitHub repositories to host six malware payloads which were frequently switched, with most of them also being signed using multiple code-signing certificates.

However, the hackers failed to sign all the malware they hosted on GitHub even though "they had access to the private key of these certificates." To top it all off, they also decided to start signing their malicious binaries using a Google certificate for which they did not have the private key.

After analyzing the code-signing certificates in this malvertising campaign, the researchers found an apparent overlap with other malicious operations such as the "Wauchos botnet as well as some adware and coin miners," which led them to believe that the operators bought them from the same distribution channels.

As discovered by ESET Research, the Yandex.Direct-powered malvertising campaign was used by the attackers to distribute the modular Buhtrap banking Trojan also known as Ratopak [1, 2, 3, 4, 5], the RTM banking Trojan, and the ClipBanker Trojan.


Malware payload distribution timeline

One of the Buhtrap modules detected while analyzing the malware dropped during the campaign was a new Delphi-based malware which was distributed between February and March 2019, dubbed by the ESET researchers Win32/Filecoder.Buhtrap.

This module comes with "the expected behavior of ransomware, discovering local drives and network shares and encrypting files found on these devices. It doesn’t require an internet connection to encrypt its victims’ files, since it doesn’t communicate with a server to send the encryption keys."

Filecoder.Buhtrap will add a so-called "token" to the ransom note it drops on the compromised system after encrypting the files and will ask the victim to get in touch with the attackers using Bitmessage or email for further instructions.

The ClipBanker Trojan was distributed between the end of October to early December 2018 and it was used to monitor the victim's clipboard for cryptocurrency addresses and replace them automatically with an address the attackers controlled.

Another variant dubbed ClipBanker.IH also targeted Steam trade offers and exfiltrated Bitcoin WIF private keys, Bitcoin Core wallets, and Electrum Bitcoin wallets using the IP Logger service.


IP Logger console

The RTM banking Trojan described in detail by ESET and Palo Alto Networks and known to have banking-related and smart card reader monitoring capabilities, as well as keylogging and screenshot modules was also dropped during Early February 2019.

A Buhtrap downloader strain was also disseminated as part of the attacks, which unlike previously detected strains of the Buhtrap backdoor which used a DLL side-loading trick, it was loaded directly into the system's memory.

As a finishing touch, the malicious actors also decided to host an Anubis banking Trojan strain in the form of a heavily obfuscated Android Application Package (APK) which was not distributed through the malvertising campaign.

GitHub-hosted malware blends in the crowd

This malvertising campaign is yet another example of threat actors using GitHub repositories to either make their malware payloads look like they're legitimate, harmless downloads or to blend in their victims' web traffic to avoid detection.

Just a few days ago, hackers were observed compromising a few hundred Magento-powered e-commerce websites and subsequently injecting them with Magecart skimmer script hosted on GitHub as discovered by Malwarebytes security researcher Jérôme Segura.

Proofpoint's research team also unearthed a malicious campaign used by bad actors to host phishing kits on the web-based GitHub code hosting platform, abusing the service's free repositories to deliver them to their victims via github.io domains.


MageCart skimmer hosted on GitHub

GitHub and Pastebin were also used to host malware for various stages of the infection chain of the SneakyPastes operation attributed to the least sophisticated division of the Gaza Cybergang hacking group according to the Kaspersky's GReAT (Global Research and Analysis Team), and targeting both organizations and individuals with politically-themed phishing emails related to Palestinian issues.

Last but not least, back in early March, Trend Micro observed a backdoor malware strain dubbed SLUB using the Github Gist service and the Slack messaging system as communication channels with its masters.

The important thing is that GitHub seems to have a very responsive support team which acted immediately according to all the researchers who reported various malicious activity using GitHub assets or infrastructure.

Update April 30 16:17 EDT: According to reports from security researchers Vitali Kremez and MalwareHunterTeam [1, 2], the ransomware module dropped as part of this malvertising campaign is actually VegaLocker ransomware.
