
	   


Oracle on Tuesday announced a patch for a remote code execution vulnerability affecting specific versions of the WebLogic Server. The bug bypasses a previously fixed flaw and researchers say it is actively used in attacks.

The issue is now tracked CVE-2019-2729 and it is deserialization via XMLDecoder in Oracle WebLogic Server Web Services. This is the same as CVE-2019-2725, patched in April, leveraged in past attacks to deliver Sodinokibi ransomware and cryptocurrency miners. It is also included in the exploit bag of the recently discovered Echobot botnet.

Old problem returns

Oracle warns in its advisory that CVE-2019-2729, with a severity score of 9.8 out of 10, "may be exploited over a network without the need for a username and password." WebLogic Server versions affected are 10.3.6.0.0, 12.1.3.0.0, 12.2.1.3.0.

Interim solution to patching

The deserialization issue is triggered by the "wls9_async" and "wls-wsat" components in Oracle WebLogic.

If patching is not possible right away, the researchers propose two mitigation solutions:

delete "wls9_async_response.war" and "wls-wsat.war" then restart the WebLogic service
	enforce access policy controls for URL access to the paths  "/_async/*" and "/wls-wsat/*
Both deserialization vulnerabilities were zero-days actively exploited by the time Oracle learned about them and released an emergency patch. They work in the same way and leveraging them leads to the same remote code execution effect. The difference is that the first one affects all versions of WebLogic Server while the second impacts specific releases of Oracle's product.

According to results on ZoomEye search engine, there are almost 42,000 instances of Oracle's WebLogic Server deployed in 2019. A similar search on Shodan shows a little over 2,300 servers available online. What both engines agree on is that these servers are mostly present in the U.S. and in China.
