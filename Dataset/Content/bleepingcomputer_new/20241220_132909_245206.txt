
	   


A new malicious campaign is distributing an upgraded variant of DanaBot that comes with a new ransomware module used to target potential victims from Italy and Poland via phishing emails which deliver malware droppers.

As initially discovered by Proofpoint researchers in May 2018, DanaBot is a modular banking Trojan developed in Delphi and designed to steal banking credentials and sensitive information by collecting form data, taking screenshots, or logging keystrokes on compromised computers.

All the data gathered during the collection phase is sent back to a command-and-control (C2) server they controlled by the banking Trojan's operators.

Each new campaign has a different ID detected by security researchers in the malware's communications with the C2 servers.

This led Proofpoint's research team to think that DanaBot is now being marketed through an affiliate system that makes it possible for various groups to either rent the malware or share the profits with its development team.

The new DanaBot variant detected by Check Point adds a "Non Ransomware" ransomware module to its previous list of capabilities which allow it to:


• Steal browsers and FTP clients credentials
• Collect crypto wallets credentials
• Runn a proxy on an infected machine
• Perform Zeus-style web-injects
• Tak screenshots and record video
• Provid a remote control via RDP or VNC
• Request updates via TOR
• Bypass UAC us a WUSA exploit
• Request updates from C&C server and execute commands


DanaBot's ransomware module was first included "in the list of available modules a new module, D932613F6447F0C56744B1AD53230C62 for a European campaign with ID=7" during late April.

Non Ransomware was discovered in the wild by GrujaRS and, according to Amigo-A, it is a Blitzkrieg Ransomware variant that changes the extension added to the encrypted files from .bkc to .non.

After encrypting all the files available on all local drives except the ones in the Windows folder, the ransomware will place a HowToBackFiles.txt ransom message in each directory containing encrypted files.


HowToBackFiles.txt Non Ransomware ransom note

Once launched, the malware will also drop a b.bat batch file in the system's TEMP folder which will be executed for:


• Enabling setting for showing hidden files
• Disabling Windows Defender
• Enabling ClearPageFileAtShutDown to purge the pagefile.sys
• Stopping services
• Stopping monitoring software (Veeam, TeamViewer, etc.)
• Disabling hibernation
• Removing logs
• Bypassing the PowerShell Execution Policy
• Disabling restoration for the following logical disks: C, D, E, F, H;
• Clearing EventLog and Recycle Bin
• Deleting shadow copies for all volumes


Next, the DanaBot ransomware module will make sure that it can revive itself in the event of getting killed by adding a new scheduled task using the legitimate Schtasks tool.

"The ransomware enumerates logical drives, visits all the directories except Windows, and encrypts all the files using AES128. The password is a string representation of the system volume serial number. Every file is encrypted in a separate thread," explain the Check Point researchers.

Additionally, "the only thing that is needed to restore the encrypted files is to call the DecodeFile function for all the encrypted files with a password bruteforced using the known victim ID."


Encrypted file layout

The ransomware will also detect the compromised machine's Windows version which it sends to the attackers encoded to Base64, together with a uniquely generated ID and the currently logged on user name.

A full list of indicators of compromise (IOCs) including dropper and C2 server addresses, as well as WebInject and redirect IPs and domains are available at the end of Check Point's extensive report.

Check Point also released a GUI-based decryptor for Non Ransomware named NonDecryptor, downloadable from HERE.
