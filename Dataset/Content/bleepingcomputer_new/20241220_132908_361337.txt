The TLS 1.3 protocol was officially approved by the Internet Engineering Task Force (IETF) on March 21, 2018, after 28 protocol drafts and four years of discussions.

As described in IETF's TLS 1.3 Internet Draft, "TLS allows client/server applications to communicate over the Internet in a way that is designed to prevent eavesdropping, tampering, and message forgery."

Last week, we shipped the first developer seed of iOS 12.2. Among other features, TLS 1.3 is now enabled by default for the entire system. All users of Network.framework and NSURLSession APIs will now negotiate TLS 1.3. The number of TLS 1.3 capable clients on the Internet should take quite a leap forward, and we are pleased to help move the needle towards faster and more secure network connections. 


When compared to the TLS 1.2 protocol which it deprecates, TLS 1.3 comes with these differences:

Removes older encryption and hashing algorithms (such as MD5 and SHA-224) and adds harder to crack alternatives (such as ChaCha20, Poly1305, Ed25519, x25519, and x448).
	Is a lot faster at negotiating the initial handshake between the client and the server, reducing the connection latency and removing the excuse of not supporting HTTPS because of lower browsing speeds.
	Supports features like Zero Round Trip Time (0-RTT) and TLS False Start designed to also cut down the time needed to establish encryption handshakes with hosts to which the client has talked before.
	Comes with downgrade attack protection that prevents an attacker from tricking a server into using older versions of the protocol, susceptible to known vulnerabilities.
Try TLS 1.3 right now on iOS and your desktop OS

The first iOS 12.2 Beta version was released by Apple to developers on January 24, and the rest of the users who wanted to test this beta seed were provided with a public release four days later.

While an exact release date for the iOS 12.2 final released rollout is very hard to estimate, most Apple pundits say that it will arrive sometime during early March and will be announced during a product or service launch event.

Those who want to try Apple's system-wide TLS 1.3 implementation in iOS 12.2 Beta can register in the Apple Beta Software Program (Apple Developer Program for developers) to enroll their devices to access the latest public beta.

If the release is too unstable or buggy for day to day use, one can easily leave the program by going to the Unenroll page and following the instructions to remove the Apple ID from the Apple Beta Software Program.

Desktop users already have access to TLS 1.3-enabled browsing if they use the latest releases of Google Chrome or Mozilla Firefox on Windows, macOS, or Linux by going to websites where the TLS 1.3 protocol is supported.

Even though Safari 11.1 does not have TLS 1.3 enabled by default, users can enable it using an undocumented settings change by running the following command in a terminal window with root privileges and restarting the Mac for the changes to take effect:

sudo defaults write /Library/Preferences/com.apple.networkd tcp_connect_enable_tls13 1

TLS 1.3 is making the Internet safer and faster

All major browser vendors (i.e., Microsoft, Google, Apple, and Mozilla) have already announced that they will be retiring the 20-year old TLS 1.0 and TLS 1.1 secure communication protocols beginning in 2020 given that roughly 94% of the sites already support TLS 1.2.

Right before this announcement, Cloudfare announced in September that it added support for encrypted Server Name Indication, a mechanism that makes it more difficult to track user's browsing, in a move designed to prevent potential attackers from seeing a target's destination IP address.

Additionally, during the spring of 2019, Google added support for the DNS-over-TLS security protocol to their public Domain Name System (DNS) service, a feature which wraps DNS queries and answers using the Transport Layer Security (TLS) protocol.

The fact that South Korea blocks HTTP websites that are on their censor list for a while now and that they have recently started using SNI filtering to block their counterparts served over HTTPS adds even more meaning to Cloudfare's initiative.
