AdGholas came to light in July 2016, when security firms Trend Micro and Proofpoint uncovered a malvertising campaign that had compromised 22 different ad networks.

The campaign, which appeared to have been running since 2013, was targeting over one million users per day and infecting thousands.

At the core of its operations was an arsenal of browser and OS vulnerabilities, including several zero-days, which the security firms reported to Microsoft.

Microsoft patched the first zero-day in September, in security bulletins MS16-104 and MS16-105. This zero-day, tracked as CVE-2016-3351, allowed the AdGholas operators to query the Windows OS (through IE or Edge) and discover if certain file extensions had been assigned to locally installed applications.

If file extensions specific to security products, virtual machines, or sandboxing environments were found, the attack would stop and skip that particular machine.

One month later, Microsoft patched a second zero-day, CVE-2016-3298, via security bulletins MS16-118 and MS16-126. This zero-day affected Internet Explorer.

Just like the first, this one allowed the AdGholas team to discover if certain files existed on disk, files specific to security products and sandboxing environments.

Third zero-day fixed in March Patch Tuesday

The third zero-day, CVE-2017-0022, was patched this month in the MS17-022 security bulletin and is similar to the first two.

This bug affects the Microsoft XML Core Services, shipped with all Windows OS services. Microsoft issued patches for all Windows versions going back to Vista, which will be discontinued next month.  This patch may be very well the last security update Vista ever gets.

"To exploit the vulnerability, an attacker could host a specially-crafted website that is designed to invoke MSXML through Internet Explore," Microsoft wrote in its security bulletin. "Successful exploitation of the vulnerability could allow the attacker to test for the presence of files on disk."

Microsoft took six months to deliver a patch

Trend Micro researchers, who spotted the zero-day in July 2016, reported this zero-day to Microsoft last September after the Neutrino exploit kit also added an exploit for this flaw to its own arsenal.

CVE-2017-0022 appears to have been developed as an alternative user fingerprinting method for the first two zero-days.

When AdGholas was first discovered, Trend Micro and Proofpoint said the group was able to target certain Windows OEM versions by searching for OEM-specific logo files on the user's PCs.

According to a technical report released by Trend Micro, the CVE-2017-0022 exploit would include a query for "RT_ICON MAKEINTRESOURCE (3)" which is a query for a "hardware-dependent icon resource," so this zero-day may be the vulnerability the two companies mentioned in their original AdGholas report.
