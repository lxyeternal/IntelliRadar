
	   


Companies can use battery status readouts of web devices to identify and track users online, warns a security researcher.

Privacy and security expert Lukasz Olejnik attributes the threat to W3C Battery Status API, a mechanism which allows web sites to read out the remaining battery level in a visitor's device as well as the time it would take for the device to recharge its battery if connected to a power source.

The API was originally designed to help site owners optimize their websites for all visitors, including individuals whose devices lack the charge necessary to view a high-power version of the site or app.

However, as Olejnik wrote in a research paper (PDF) published in 2015, there are several privacy issues with the Battery Status API. For example, those with access to the API could analyze the frequency of a device's charges to monitor users' habits and analyze their behavior, such as by looking out for times when the device is under heavy use. An actor could also recover battery capacity or even use the information provided from the API as a short-lived identifier.

Olejnik explains more in a blog post:


"An example web script continuously monitors the status of identifiers and the information obtained from Battery API. At some point, the user clears (e.g.) all the identifying cookies. The monitoring web script suddenly sees a new user - with no cookie - so it sets new ones. But battery level analysis could provide hints that this new user is - in fact - not a new user, but the previously known one. The script's operator could then conclude and reason that those this is a single user, and resume with tracking. This is an example scenario of identifier recreation, also known as respawning."


Given those issues, it's not surprising companies are making use of information provided by the Battery API to track users online.

On 11 July, researchers Steven Englehardt and Arvind Narayanan of Princeton University published a research paper (PDF) in which they explain how actors are using the API in the wild to track users. Those entities are currently leveraging two scripts: one that tracks battery readings and combines that with other fingerprint data from the device, and another that obtains the charging status, charge level, and the time remaining to discharge or recharge. Together, those scripts provide more than enough information for actors to continously monitor people online.

But the use of trackers might not end there. As Olejnik observes:


"Additionally, some companies may be analyzing the possibility of monetizing the access to battery levels. When battery is running low, people might be prone to some - otherwise different - decisions. In such circumstances, users will agree to pay more for a service."


As a result of these findings, a few browser vendors are reconsidering providing site owners with access to the API. The maker of the API has also updated one of its standards to reflect the ongoing research into this subject.
