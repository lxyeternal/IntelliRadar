
	   


This month has been quite eventful for D-Link. As reported by BleepingComputer, the company’s router firmware images have been leaking the secret key used to encrypt their proprietary firmware binaries.  

Now, the company has disclosed five severe vulnerabilities in some of their router models, which could allow a severe network compromise. Moreover, some devices have reached their "end of life" phase, which means they wouldn't be patched.

The vulnerabilities reported by ACE Team – Loginsoft include reflected Cross-Site Scripting (XSS) attacks, buffer overflows to means of obtaining admin credentials, bypassing authentication altogether, and executing arbitrary code.

It becomes much more problematic for those users who enable remote access to the D-Link router's web administration interface.

If the remote admin interface is enabled, all a remote attacker would need to do is make a simple request to the router's public IP address, bypass authentication, and take-over the device and the network.

Unfortunately, routers with remote administration enabled are not rare.

According to IoT search engine Shodan.io, over 55,000 D-Link devices have remotely accessible web interfaces.


Shodan showing over 55,000 accessible D-Link routers
Source: BleepingComputer

It should be noted that while many of these D-Link devices may not be vulnerable, it does illustrate how too many of them have remote administration enabled.

Proof of Concept exploits released

The Loginsoft advisories include proof of concept (PoC) exploits that illustrate how easy it is to abuse the newly disclosed D-Link vulnerabilities.

Authentication bypass backdoor

To demonstrate the simplicity of just one vulnerability, CVE-2020-15896, say the D-Link router’s administration interface runs on 192.168.0.1, or a publicly accessible IP.

Usually, to access a restricted page like ‘/bsc_lan.php,’ you would need to provide the router’s administrator username and password.

With this vulnerability, simply appending the GET parameters `NO_NEED_AUTH=1` and `AUTH_GROUP=0` to the URL, it acts as a backdoor and circumvents the need to login to the admin interface.

The complete access control bypass URL would look like:

http://192.168.0.1/bsc_lan.php?NO_NEED_AUTH=1&AUTH_GROUP=0

CVE-2020-15896 impacts the later firmware versions 1.41 & 1.42 on D-Link DAP 1522 devices (Ax Hardware). 

In 2010, the same flaw was reported by a pentester and researcher at Safe Computing at the time.

In 2011, a PoC exploit posted by Craig Heffner of /dev/ttyS0 further confirmed the presence of the same vulnerability on DIR-320 and DIR-615 revD devices as well.

Other reports on Heffner’s exploit page demonstrate variants of the vulnerability existed in routers since at least 2009. 

Surprisingly, router manufacturers have continued to neglect to patch these severe flaws in all these years, leaving even modern devices at the mercy of attackers.

Show me usernames and password hashes

Similarly, the exploit for CVE-2020-15894 impacting Bx hardware devices entails accessing the following URL on the router’s IP:

http://192.168.0.1/getcfg.php?a=%0a_POST_SERVICES%3DDEVICE.ACCOUNT%0aAUTHORIZED_GROUP%3D1


The payload here being, “_POST_SERVICES=DEVICE.ACCOUNTAUTHORIZED_GROUP=1”
This exploit will return to the attacker a response containing a list of usernames (e.g., “admin”) and hashes of the password.

The vulnerability impacts Bx hardware devices running firmware 2.06 & 2.06.B09_BETA and below, as listed in the exploit.

Remote command injection

CVE-2020-15893 is concerned with the ability to execute arbitrary commands by the attacker with access to the router’s IP via UPnP crafted “M-SEARCH” packets. 

“Universal Plug and Play (UPnP), by default is enabled in DIR-816L, on the port 1900. An attacker can perform command injection by injecting the payload into the `Search Target` (ST) field of the SSDP M-SEARCH discover packet,” stated Loginsoft’s advisory. 


A simple PoC code enabling command injection via crafted UPnP requests
(Source: Loginsoft ACE Team)

The vulnerability impacts Bx hardware devices running firmware 2.06 & 2.06.B09_BETA and below, as listed in the exploit published by Loginsoft.
The recommendation made by Loginsoft ACE Team to mitigate the vulnerability is to follow a blacklisting approach “to filter out command injection-related payloads, such as `;` `||` etc.”

D-Link’s response

In a comprehensive advisory covering all CVEs, D-Link released a list of all vulnerable firmware versions and hardware devices. 

Some of the vulnerabilities were reported as early as February  9, 2019, according to D-Link, whereas some of the Loginsoft advisories date back to March 2020.

All 5 CVEs, however, have only been publicly revealed on July 22, 2020, as per NVD. 

There is more to the story, though.

No consideration has been given to models DAP-1522 and DIR-816L that have reached their “end of support” phase. These devices running firmware versions v1.42 (and below) and v12.06.B09 (and below) remain vulnerable with no upgrade path.

For the D-Link DAP-1520 model running vulnerable firmware versions v1.10B04 and below, the company has released an “Exceptional Beta Patch Release” firmware version v1.10b04Beta02 that users could upgrade to.

Therefore, users who are running these devices have no means of upgrading and will continue to remain vulnerable unless they purchase newer devices.
