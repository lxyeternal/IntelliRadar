
	   


Google has announced that as of October 2019, 80% of all Android apps are now using Transport Layer Security (TLS) to encrypt their network traffic.

Since 2017, Google has been pushing Android developers to integrate encrypted traffic into their apps in order to provide better security and privacy as apps communicate over the Internet or on a network. 

Starting with Android 7 in 2016, Google introduced the Network Security Configuration file, which allows app developers to opt out of using cleartext when performing network communication. In Android 9, released in 2018, Google took it a step further and made it so that any apps targeting Android 9 or higher would automatically use a default policy that prevents apps from using unencrypted traffic.

This amount will likely increase over time as on November 1st, 2019, Google has made it a requirement that all updates and new apps submitted to the Google Play Store must target at least Android 9.

Dev tools make it easier to support encrypted traffic

To make it easier for app developers to use encrypted traffic in their apps, the latest version of Android Studio will now warn devs if their apps are using a potentially insecure Network Security Configuration.


Android Studio warning

As a final warning, when developers upload their Android app's apk file to the Google Play Store, a pre-launch report will be generated by test devices that automatically analyze the app.  If insecure network communication is detected, the pre-launch report will warn the developer.


Pre-launch report warning

Developers can determine if their apps are allowing cleartext network communication by analyzing their Network Security Configuration file and checking the values for the cleartextTrafficPermitted directive.

Google advises that if at all possible, no domains should be whitelisted for cleartext communications and encrypted traffic should be used instead.
