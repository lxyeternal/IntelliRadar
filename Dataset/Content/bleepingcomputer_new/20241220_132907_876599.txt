
	   


The National Security Agency released a free, public version of Ghidra, a set of tools developed internally for software reverse engineering. The agency will also release Ghidra's source code, allowing users to improve the framework's feature set and turn it into a more effective tool.

Ghidra became known in the security community after WikiLeaks published the "Vault 7" documents, which referenced it as a reverse engineering tool created by the NSA's Research Directorate, among hacking tools used by the Central Intelligence Agency.

If you're wondering why the NSA made these tools available, senior advisor for the NSA Robert Joyce said the move was powered by the need to improve cybersecurity tools, to build a community, to educate new talent, and to show what the agency uses the tax money for.

Ghidra comes with powerful capabilities

Malware researchers have been expecting the release of the toolkit with excitement, especially since people familiar with it compared Ghidra to professional software with licenses of thousands of dollars, like IDA Pro.


The same capabilities with IDA Pro would cost you ~$13,000 (and it supports less architectures). As much as I love IDA, their monopoly is the bane of my existence.
— MalwareTech (@MalwareTechBlog) March 6, 2019

On Tuesday, at the RSAConference in San Francisco, the NSA rolled out a version of Ghidra for the public, available for macOS, Windows, and Linux on a dedicated website. A GitHub repository is also present, where the code is expected to be published. Joyce spoke (slides here) about how the toolkit can be used and discussed its strong points.



The description says that it comes with "context-sensitive help on menu items, dialogs, buttons and tool windows, which makes it suitable for those that want to break into reverse engineering.

Furthermore, it is presented as a collection of high-end analysis tools for disassembly, assembly,  decompilation, graphing, and scripting, and counting hundreds of features.

"Ghidra supports a wide variety of process instruction sets and executable formats and can be run in both user-interactive and automated modes. Users may also develop their own Ghidra plug-in components and/or scripts using Java or Python," reads the description on GitHub.



Most of the researchers that played with Ghidra gave it positive reviews, applauding both its list of features and the help documentation and exercises for different skill levels.




My favorite part of Ghidra is the side-by-side disassembler/decompiler. It's a total game changer for those looking to break into the industry.
— MalwareTech (@MalwareTechBlog) March 6, 2019

Security researcher Marcus Hutchins of Kryptos Logic live streamed a video review of Ghidra, and declared himself pleased with the features of the project, but not with the interface (and for good reason).

"So far I'm liking this more than I thought I would," Hutchins says toward the end of the video.

Although the interface is not modern-looking, Ghidra comes with a huge list of analysis options:



Patrick Miller, security researcher, Raytheon Intelligence, Information and Services, told BleepingComputer that "Ghidra is comparable to IDA and Binary Ninja, as all three tools have distinct specialization that make them valuable in a reverse engineer’s tool kit."

The suite should be a valuable asset to cyber teams that do not have sufficient resources to move forward at a competitive pace. The proficiency of this category of users should receive a boost with the release of Ghidra.

"As a user of this tool for years, I cannot wait to see how it improves in the hands of my peers," Miller added.



Several researchers have stated that the framework's features are comparable to those in commercial reverse engineering software. Miller has the same opinion and is confident that by open-sourcing the code, NSA's suite will only improve in time.



The support for Java and Python scripts can extend its list of features, and module will only make it more powerful. Ghidra is a fantastic opportunity for researchers that were confined to limited versions of commercial tools, which, although better than nothing, allow analysis only up to a certain level.

Those looking for the dark side of Ghidra's interface can turn it on by inverting the colors in the Edit>Tools Options>Tools of the main project window.



First remote code execution bug reported

Shortly after the release of the tool, Matthew Hickey, co-founder and head of Hacker House security outfit, found a bug triggered when Ghidra runs in debug mode. It opens the Java Debug Wire Protocol (JDWP) and listens for network connections on port 18001. This can serve for remote code execution, the security expert tweeted.

The debug mode is not active by default and the problem has a simple solution: change the launcher shell script so that it listens to connections from the local machine only. This is a clear indication of a bug rather than intention to compromise computers of professionals reversing malware.



When his discovery was challenged Hickey defended that even when debugging the possibility for someone to run code remotely on the machine should not exist.

Despite being available for a short time, Ghidra received a lot of attention and the list of issues (not all of them bugs) on its GitHub page reached 28, with five already closed.
