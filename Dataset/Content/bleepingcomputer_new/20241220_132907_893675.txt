
	   


Over the weekend, hundreds of popular Israeli sites were targeted by an attack called #OpJerusalem whose goal was to infect Windows users with the JCry ransomware. Thankfully, a mistake in the attacker's code caused the page to show a defacement rather than causing the ransomware to be distributed.

To orchestrate this attack, the attackers modified the DNS record for a popular web accessibility plugin from nagich.com. When visitors went to a site that was utilizing this plugin, a malicious script would be loaded instead of the legitimate plugin.

Ido Naor, Principal Security Researcher at Kaspersky Lab, explained to BleepingComputer that a mistake in the attackers code only showed the defacement rather than distributing the JCry ransomware infection.

The #OpJerusalem attack

With malicious script shared by Naor with BleepingComputer, we can see how the attack was intended, but ultimately failed, to be conducted.

The attacker's script would check the browser's user agent to determine if the visitor was running Windows. If the variable was equal to the specific string "Windows", the site would display a fake Adobe update message that is used to distribute the JCry Ransomware.  Otherwise a defacement page would be displayed.


Script to check for Windows

The attackers messed up and the variable was never set to only "Windows", but rather to the Windows version such as "Windows 10" or "Windows 7", so everyone was shown a defacement page instead. This defacement page contained the text "Jerusalem is the capital of Palestine #OpJerusalem" as shown below.


#OpJersusalem Defacement Page

If the attackers had properly coded the script, though, they would have been shown as screen that pretends to be a notification that the user must update their version of Adobe Flash Player.


Fake Adobe Update Message

When clicking on the Update button, an executable called flashplayer_install.exe would have been downloaded.


JCry Ransomware Executable

This executable, though, is not a Flash Player updater, but rather the executable for the JCry ransomware.

The JCry Ransomware

When executed, the JCry ransomware will extract two files called dec.exe and enc.exe to the victim's Startup folder. The enc.exe file would then be executed and begin to encrypt the data on a victim's computer.


Extracted Files

When encrypting a file, the ransomware will append the .jcry extension to an encrypted file's name as shown below.


Encrypted jcry Files

After the ransomware finishes encrypting a computer, the decrypter will automatically be launched wait for a a decryption key to be entered.


JCry Decrypter

The ransomware will also create a ransom note named JCRY_Note.html, which contains a victim's unique key, a bitcoin address to send the $500 ransom payment, and a TOR site with the address http://kpx5wgcda7ezqjty.onion, which used to tell the attackers a payment has been made.


JCRY Ransom Note

This TOR site simply contains a field that you would enter the address of the wallet you sent the payment from and your prefilled unique ID. 


JCRY TOR Site

As the 1FKWhzAeNhsZ2JQuWjWsEeryR6TqLkKFUt bitcoin address used for payment is the same for every victim, if this was a real ransomware and not a wiper, it would have been hard for the attackers to know who actually made the payment. It could have also allowed unscrupulous victims to try and steal other user's payments.

It is not know whether the attackers would have provided a key after paying the ransom.
