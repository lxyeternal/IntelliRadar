
	   


Android malware is evolving, and a clear trend has become visible in the past six months, with several malware strains implementing their malicious behavior via plugin frameworks.

DroidPlugin, Parallel Space, and VirtualApp are the names of several plugin frameworks that have been abused by malware in recent months to spread Android malware, and especially adware.

Plugin frameworks were created to help Android developers

The role of such tools is to extend the Android OS with non-native features. Their primary role is to add support for virtualization, allowing the Android OS to run a virtual machine where another instance of the same app can run.

It's because of plugin frameworks that some social media apps allow users to log into two or more Facebook or WhatsApp accounts at the same time.

Other apps have also used plugin frameworks to support "hot patching," a technique that allows the delivery of app updates from outside the official Google Play Store.

Plugin frameworks increasingly abused to spread malware

Unfortunately, malware authors have discovered the benefits of Android plugin frameworks as well.

In October 2016, Avast researchers found that crooks were using VirtualApp for phishing attacks aimed at Twitter and WhatsApp users.

In November 2016, Palo Alto Networks discovered PluginPhantom, a new Android trojan that used the DroidPlugin framework to split malicious behavior across multiple plugins, making detection much harder.

In January 2017, Check Point unearthed a new version of the HummingBad malware, called HummingWhale, which used DroidPlugin to install unwanted apps inside a virtual machine and earn crooks a profit in pay-per-install schemes.

New malware attacks discovered using plugin frameworks

Similarly, today, Palo Alto Networks came across a new wave of Android apps, many available on the Google Play Store, which were infected with HummingWhale.

According to researchers, the apps would contain both legitimate functionality, and malicious behavior. The malicious behavior would always take place inside a virtual machine created with the DroidPlugin framework.

In some cases, the malware would use the plugin framework to launch another instance of the same app, but which only showed a wall of ads. In other cases, the malware would go one step further and install and even launch one of these promoted apps.

The good news is that these apps would live on the device for small periods of time, as they would be automatically deleted after the virtual machine (malicious instance of the legitimate app) would terminate.

There's a way to spot apps with virtualized malware

Users can recognize if an app is using virtualized instances to show ads and install unwanted apps by accessing the Android OS screen that shows currently running apps.


Two instances of the same app, one good, the other malicious (Palo Alto Networks)

In the image above, it's evident that two instances of the same app are running. While one appears to be legitimate, the other clearly shows an ad.

Palo Alto says it reported to Google, who removed all the apps it detected that engaged in this type of behavior.

Currently, only Android adware appears to be using plugin frameworks, but mobile banking trojans also stand to benefit from using virtualization tools, as this could be an easy way to launch malicious versions of legitimate apps.
