
	   


A memory leak vulnerability in IBM Db2 relational database could allow an attacker to gain access to sensitive data or cause a denial-of-service (DoS) condition in the database.

The flaw affects IBM Db2 versions for Linux, UNIX, and Windows (9.7, 10.1, 10.5, 11.1, 11.5). It originates from improper usage of shared memory and exploitation is possible by sending a specially crafted request.

Missing access protections

Tracked as CVE-2020-4414, the issue is with the shared memory used by the Db2 trace facility, which lacks explicit protections, allowing read and write access to a local attacker.

IBM released a patch for the vulnerability on June 30 but the security bulletin provides little information:


“IBM Db2 could allow a local attacker to perform unauthorized actions on the system, caused by improper usage of shared memory. By sending a specially-crafted request, an attacker could exploit this vulnerability to obtain sensitive information or cause a denial of service” - IBM


In a blog post today, Martin Rakhmanov, Security Research Manager, SpiderLabs at Trustwave, details how an attacker could exploit CVE-2020-4414.

He explains that launching a tool, like Process Explorer, that checks for open handles of the Db2 main process, shows that there permissions for accessing the shared memory are missing.



Using a custom command line application, the researcher was able to test if content in a specific memory section could be accessed and dumped.

After enabling Db2 tracing, Rakhmanov could see what was written to the given memory locations, as seen in the screenshot below:



The researcher concludes that an attacker could write incorrect data over the target memory area to make the database inaccessible, thus causing a DoS.

Accessing the shared memory area for the database can have other implications apart from stealing data and deny service. Rakhmanov told BleepingComputer that hackers compromising a system running Db2 could use stolen sensitive data and use it in a subsequent or to further their attack.

Answering a question on whether this is a wide-spread issue, the researcher said that the issue exists in some database products but he could not label it as a “growing” concern.
