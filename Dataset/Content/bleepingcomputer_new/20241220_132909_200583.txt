The cryptojacking campaign targeting exposed Docker hosts was unearthed by Trend Micro researchers after a Docker image containing a Monero (XMR) cryptocurrency miner binary was deployed on one of their honeypots.

This type of attack is definitely nothing new seeing that researchers from Imperva discovered a similar campaign abusing the CVE-2019-5736 runc vulnerability to deploy cryptominers during early-March.

However, the hackers behind the attacks discovered by Trend Micro now also use scripts designed to scan for more vulnerable machines via Shodan search queries scanning for hosts with the 2375 port open and deploying more infected containers to the new targets after brute-forcing their way.

The same malicious campaign was also observed by a security consultant and the Alibaba Cloud Security team which named it Xulu based on the username it uses to mine for Monery cryptocurrency.

According to Nianjing Wu, Senior Security Engineer at Alibaba Cloud, "Docker’s Remote API can also be vulnerable to unauthorized access when improperly configured. Similar to the process employed in the Redis attack, an attacker can gain unauthorized access to the Docker data, steal or tamper with sensitive data, and take control of the server."

The attackers use the exposed APIs to execute commands on the Docker hosts which allow them to manage containers (start, stop, or kill), as well as create new ones by deploying a images from a Docker Hub repository they control.


Abusing Docker exposed APIs

Trend Micro's honeypot data traffic and logs pointed to a Docker Hub user named zoolu2 which hosted "nine images comprised of custom-made shells, Python scripts, configuration files, as well as Shodan and cryptocurrency-mining software binaries" in his repository.

While Docker did find the repository containing the infected Docker containers and took it down (Shodan also disabled the accounts used to access its API), at least one of them is still available and, from the info displayed on its entry, it seems that it was already deployed more than 10,000 times.

From previous reports, the attackers used another Docker Hub account to host their infected containers which was also deactivated and they keep moving them to other accounts after the old ones get disabled.

According to one of the GitHub users who have reported this malicious activity:


This image is a worm/botnet/whatever targeting unsecured Docker API instances (port tcp/2375).
It uses Tor to update its mining config and continuously scrapes Shodan for exposed Docker instances (with a hardcoded user/pass which I changed) to infect them as well. It also sets up an SSH server, with a hashed password for the root user (basically a backdoor account).



Infected container Docker Hub entry

The malicious Docker images are deployed automatically using a script which "checks hosts with publicly exposed APIs" and "uses Docker commands (POST /containers/create) to remotely create the malicious container." The same scripts also starts a SSH daemon used for remote communication with the attackers.

A custom built Monero coin-mining binary is also launched in the background while, at the same time, the scanning process for more victims is started with the help of a third script which starts a search using the Shodan API.

The list of vulnerable hosts gets written to an iplist.txt file which is checked for duplicates, with all the new targets also being scanned for existing cryptocurrency-mining containers which will be deleted if found.

The entire list of IP addresses is then sent to the campaign operators' command-and-control servers "to deploy additional containers to other exposed hosts based on the IP list. It then loops to the beginning of the routine stated earlier with a new host."
