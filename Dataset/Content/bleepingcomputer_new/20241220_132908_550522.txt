
	   


MikroTik on Thursday published details about an issue that is easy to exploit remotely to cause a denial-of-service (DoS) condition on devices running RouterOS, which is most products from the maker.

The latest updates for the operating system are meant to address the problem, but they do not have the same effect on all devices and some of them continue to be vulnerable.

Belated patch good for some devices only

Tracked as CVE-2018-19299, the vulnerability affects unpatched MikroTik equipment that routes IPv6 packets. To bring the system down, all an attacker has to do is send a specific string of IPv6 packets that would increase RAM usage on the router.

Data from Akamai on April 1 shows that India is the country delivering most of the traffic over IPv6 (63.3%) followed by Saint Barthelemy (St. Barts) French-speaking Caribbean island (51%) and the United States (46.5%).

The Latvian vendor explains in a blog post that the flaw "caused the memory to be filled because IPv6 route cache size could be bigger than the available RAM." To fix it, the new RouterOS can calculate the cache size based on the memory available on the device.

This fix is present in the current stable (v6.44.2) and long term (v6.43.14) release versions of RouterOS but it works only devices with more than 64MB of RAM, says Marek Isalski, CTO at Faelix - an ISP, hosting, and security provider based in Manchester, UK.



This was Isalski's conclusion after testing on MikroTik hardware with 64MB of RAM. MikroTik trainer Javier Prieto found the vulnerability independently, as did other network engineers, and he noticed that if the routers with RouterOS 6.44.2 do not crash if they have enough memory.

Using Cloud Hosted Router (CHR), a version of RouterOS optimized to run in a virtual machine, with 256MB of RAM, Prieto saw that the system showed 197MB free before the attack. "During the attack, only from one computer, the free memory decreases to around 20 MiB and sometimes to 13 MiB," he shared on MikroTik forum.

Isalski is the one who found the vulnerability and reported it to MikroTik last year, on April 16, according to an abridged version of the timeline he provided. He says that the company acknowledged the issue and classified it as a "not a security vulnerability." In mid-March, he alerted various cyber response groups of the vulnerability and provided evidence of its exploitation in the wild.

Optimizations expected for low RAM devices

Mitigating against this DoS risk is not possible by setting up filters in the RouterOS firewall because whatever causes the memory exhaust can be set with any IPv6 packet.

If IPv6 functionality is enabled (it's inactive by default), Isalski said that CVE-2018-19299 "affects almost any of MikroTik's devices, even those used as 'core' or 'backhaul' routers."

He strongly recommends network operators that switched to the IPv6  communications protocol to test and deploy RouterOS 6.43.14 and 6.44.2 "as soon as they can."

More than 20 RouterOS versions have been released since MikroTik learned about the vulnerability. One reason for this, besides dismissing its security risk, is that flaw is at kernel level and it is very difficult to fix. A member of the company's support team said that RouterOS v6 has an older kernel version and it cannot be changed.

For hardware with low RAM resources, optimizations are expected in the next beta version of RouterOS. The release date is currently unknown, though.

Isalski will provide technical details about the vulnerability on April 9, in a talk at the UK Network Operator's Forum (UKNOF) that will be live-streamed. The network security engineer will also present the full timeline of his interactions with MikroTik to fix the issue.

The conference is one of the reasons the topic has become known to a wider audience and contributed to MikroTik starting to work on a patch.
