
	   


The WordPress team has addressed a security flaw in the API servers responsible for the CMS' update mechanism, which if exploited, would have allowed an attacker to deploy backdoors and malware to 27% of all websites on the Internet.

Ironically, the news about this fix came hours after Scott Arciszewski, Chief Development Officer at Paragon Initiative Enterprises, had publicly criticized the WordPress team for ignoring the bad design of their CMS update system.

Arciszewski's criticism has nothing to do with the issue fixed by the WordPress team, which is a bug discovered by WordFence engineer Matt Berry.

The flaw Berry identified affects the API servers located at api.wordpress.org. Among many of the functions these servers must perform is to answer an hourly query from all sites on the Internet running WordPress.

Websites ask this domain if there's a new WordPress core, plugin, or theme version available, and if there is, the API server sends the new version number and a download location from where sites can download the new package.


WordPress API server infrastructure (via WordFence)

Developers that work on the WordPress core, plugins, or themes, could push code from their GitHub repos to the WordPress internal SVN servers. Berry found that when they pushed a new version, GitHub would also contact the WordPress API servers and inform it of the newly pushed version.

The WordFence engineer says this WordPress API - webhook - GitHub interaction could be downgraded to use a weak hashing function in the authentication process.

This allowed Berry to bypass the authentication procedure, and send POST requests to the API server itself.

Berry also discovered that there is a POST parameter for the GitHub project URL that is passed unescaped to the API server's shell. This meant that an attacker could push code from a GitHub repo, bypass the WordPress API server authentication, and execute commands on the API server, taking it over from the WordPress team.

The WordPress update mechanism is a highly valuable target

The bug that Berry discovered fits right into Arciszewski's apocalyptic scenario that he described a day earlier. An attacker could take over the WordPress update mechanism and push malicious code to millions of sites on the Internet.

Because local WordPress installations only use an MD5 checksum to verify the update package they receive, attackers could push malicious code almost simultaneously to a large number of WordPress sites.

Arciszewski described WordPress' update system as a Single Point Of Failure (SPOF), something that almost all companies avoid when building their infrastructure. He also recommended replacing the MD5 checksum check with a cryptographic signature that's much harder to fake.

Berry and the WordFence team say they reported the API server bug to the WordPress team via the HackerOne bug bounty program, for which they received a monetary reward.

The flaw, which accounted for a 9.8 severity score out of a maximum of 10, was reported at the start of September, and fixed five days later. Webmasters don't need to apply any update, since the patch was pushed to the WordPress API servers.
