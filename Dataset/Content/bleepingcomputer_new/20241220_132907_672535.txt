
	   


As part of the August 2020 Patch Tuesday, Microsoft fixed a vulnerability that allowed MSI files to be converted into malicious Java executables while retaining a legitimate company's digital signature.

This vulnerability is tracked as CVE-2020-1464 and is described by Microsoft as a spoofing vulnerability in how Windows validates signature files.


A spoofing vulnerability exists when Windows incorrectly validates file signatures. An attacker who successfully exploited this vulnerability could bypass security features and load improperly signed files.

In an attack scenario, an attacker could bypass security features intended to prevent improperly signed files from being loaded.


It was later noted in a blog post by security researchers Tal Be'ery, of Zengo, and Peleg Hadar, of SafeBreach Labs, that this update is for a bug reported two years ago on August 18th, 2018, and that Microsoft originally stated they would not be fixing.

In January of 2019, Bernardo Quintero of VirusTotal disclosed how a malicious signed Java executable was uploaded and detected by their VirusTotal Monitor service in 2018.


Malicious JAR file submitted to VirusTotal in 2018

After examining the .jar file, Quintero discovered that the malware was an MSI file with a Java JAR file appended to it.

Even though this MSI file was tampered with and renamed to a JAR file, the problem was that Windows still consider the file to be signed by a valid certificate from Google, as shown below.


Malicious JAR file showing as signed by Google

As some security solutions utilize a digital signature to determine if an unknown file should be allowed to run, a threat actor could use this technique to create Java malware that bypasses security software.

After discovering this flaw, Quintero responsibly disclosed it to Microsoft on August 18th, 2018, but was told it would not be fixed.

"This attack vector has been verified in the latest and updated versions of Windows 10 and Java available at the timing of writing (Windows 10 Version 1809 and Java SE Runtime Environment 8 Update 191). Microsoft has decided that it will not be fixing this issue in the current versions of Windows and agreed we are able to blog about this case and our findings publicly," Quintero explained in his disclosure.

To help detect these types of malicious JAR files, both VirusTotal added detection for these tampered files in their analysis, and SysInternal's sigcheck tool was updated to detect them as well.

With the patch for CVE-2020-1464, Windows will no longer considered MSI files to be signed if they have been tampered by having a JAR file appended to it.

Microsoft's fix can be seen when we look at the properties of a malicious JAR file that used this technique in Windows 10 1909 (left) and Windows 10 2004 (right) below.


Malicious JAR file properties before and after fix

In BleepingComputer's tests, this security update only removes digital signatures on MSI files modified by a JAR file.

If you append a .exe executable to a signed MSI file, the MSI's signature will continue to remain valid, indicating it has not been modified.

In 2019 when we covered this issue, Chronicle had told BleepingComputer that this should not be an issue as only JAR files could exploit this issue.

"This technique has proven, so far, to be extremely rare. While you can append anything to the end of an MSI, in this particular case, only a JAR would execute in the manner described by the original blog post." Chronicle told BleepingComputer in our 2019 report on this issue.

It is not known why it took Microsoft two years to fix this issue and why Quintero was not attributed as the person who disclosed the flaw.

BleepingComputer has contacted Microsoft with these questions but has not heard back as of yet.

Why can you tamper with MSI files?

You can tamper with MSI files without invalidating the signature due to how these files are read.

According to Tal Be'ery, when Windows reads an MSI file, it reads it from the beginning of the file until the end of a valid MSI signature and discards the rest.

Therefore it ignores the appended data, regardless of what it is, after a valid MSI file structure is detected.

As we reported in 2019, JAR files are simply ZIP files, and when executed is read by the JAVA runtime starting with the end of the file until the beginning of a valid ZIP file structure is detected. It then discards the rest of the file.


Zip Internal LayoutSource: Wikipedia

As Windows reads from the beginning and JAVA reads from the end, it allows the operating system to see the JAR file as a legitimately signed file.

At the same time, JAVA reads a JAR file from the end and discards the rest.

When combined, we had a working method for malicious actors to create malicious JAR files, while spoofing legitimate company's digital certificates.
