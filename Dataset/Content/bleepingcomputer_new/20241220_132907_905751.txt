Security researchers from Qualys discovered a new username enumeration problem in the latest version of OpenSSH. It allows an attacker to try out various usernames on the server and determine which ones are valid. The vulnerability received tracking number CVE-2018-15919.

Qualys spotted the issue in the same way as the previous one reported last week, while analyzing a commit in the suite's OpenBSD source code.

Qualys researchers explain that when a user tries to authenticate, the attacker receives the same packet whether the user is valid or not.

"However, if the user is valid, then 'server_caused_failure' is set," the researchers say in an advisory, adding that this does not happen when providing a user that does not exist on the server.

They detail that the default number of attempts for an invalid user is limited to six, then the server disconnects the attacker. If a valid user is provided, "the attacker can attempt the GSSAPI authentication indefinitely." This leaves the door open to brute-force attacks on the password.

OpenSSH developers do not consider fixing this vulnerability a priority because of its low severity level. The reasoning is that "it's a partial disclosure of non-sensitive information."

They say that the bug allows "an attacker to make brute-force guesses of account names and verify whether they exist on the target system." The six-attempt limitation narrows the chances of success even more.

Open-source developer Damien Miller working on OpenSSH says that system libraries do not treat this type of information disclosure as a threat because usernames are considered the non-secret part of user identity, useless to an attacker without the accompanying password.

A sophisticated attacker can benefit from this type of flaw during the reconnaissance stage, helping them determine which attacks would be more successful, says Jimmy Graham, Director of Product Management at Qualys.

"Specific users on a system can often give away the exact operating system or distribution, as well as services that are running on the system, especially if they have default usernames for those services," Graham told BleepingComputer.

Graham admits that oracle attacks are not a significant threat, but they should be treated as security issues, nonetheless, because they expose user information.
