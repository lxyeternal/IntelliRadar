
	   


A malicious campaign targeting entities from North America, Europe, Asia, and the Middle East during March used a combination of pages hosted on Bit.ly, BlogSpot, and Pastebin to create a command-and-control (C2) infrastructure designed to avoid getting blocked by security solutions.

Palo Alto Networks' Unit 42 discovered that the threat actors behind the campaign dubbed "Aggah" employed the C2 infrastructure built using only legitimate services to drop RevengeRAT (also known as Revetrat) payloads on organizations from "Technology, Retail, Manufacturing, State/Local Government, Hospitality, Medical, Technology, and other Professional business.

RevengeRAT is a publicly available Remote Access Trojan released during 2016 on the Dev Point hacking forum and it is known to be capable of opening remote shells, allow the attacker to manage system files, processes, and services, edit the Windows Registry, track the victim's IP address, edit the hosts file, log keystrokes, dump users passwords, and access the webcam, among many others.

Also, "These macros use BlogSpot posts to obtain a script that uses multiple Pastebin pastes to download additional scripts, which ultimately result in the final payload being RevengeRAT configured with a duckdns[.]org domain for C2."


Lure image used in decoy document

The campaign was first detected by Unit 42 on March 27 after the decoy file camouflaged to look like an official document from a financial institution with a "Your account is locked" email subject was sent to entities from a Middle Eastern country.

Not long after, just four days later, the Aggah campaign expanded to other Middle Eastern countries, later on being spotted while spreading to new potential victims from North America, Asia, and Europe.

Multi-stage infection process

After the decoy document was opened on a target's computer, it would immediately display a lure image designed to trick the user into turning on Microsoft Office macros to "Enable Editing." If the victim falls for it, a remote OLE document containing the malicious macro would be loaded using template injection.

In the next step of the infection process, the OLE file loaded an embedded Excel document which would decode an execute a download command from a URL shortened using the Bit.ly service, which expands to a Blogspot domain where a malicious JavaScript is hosted.

Once downloaded on the compromised machine, the malicious script will carry out "several activities on the compromised system. First, it attempts to hamper Microsoft Defender by removing its signature set. The script also kills the Defender process along with the processes for several Office applications."


Number of clicks on one of the payload download links

The script will then move to the next stage, also disabling ProtectedView and enabling macros for the Word, PowerPoint and Excel Office apps on the infected computer.

After being downloaded on a victim's machine, the script will perform the following main actions: 


• Downloading a payload from a Pastebin URL
• Creating a scheduled task to periodically obtain and run a script from a Pastebin URL
• Creating an autorun registry key to obtain and run a script from a Pastebin URL


The final malware payload downloaded from Pastebin is a RevengeRAT variant dubbed "Nuclear Explosion" configured by the threat actors to use the lulla.duckdns[.]org domain as its C2 server.

During the campaign analysis, the researchers discovered that a single bit.ly link was clicked over 1,900 times by targets from roughly 20 countries, a fact which shows the magnitude of the campaign given that the IOCs list contains 33 different bit.ly download links used in the attacks — these are just the ones the researchers were able to get a hold of.


RevengeRAT configuration

Additionally, after looking into the decoy document's properties, Unit 42 was able to find a number of other RevengeRAT samples connected to the campaign, as well as a few other C2 domains. The information collected during the Aggah campaign analysis process also showed that documents connected to the campaign operators have timestamps which span between January and April 2019.

As discovered by Unit 42's research team, "enabling macros and disabling ProtectedView in Office," "the order in which the registry keys were modified," "the tactic of killing processes for Windows Defender and Microsoft Office applications," and the tactic of using "bitly URL shortening service in their attacks" overlap with malicious techniques used by the Gorgon Group (aka Subaat), tracked starting with February 2018, supposedly having in its malware toolset a number of other RATs such as NanoCoreRAT, QuasarRAT, and NJRAT.

Despite this, the Palo Alto Networks researchers say that there is no "concrete evidence that this attack campaign is associated with Gorgon."
