Mozilla engineers are working on a patch to fix a zero-day exploit that's currently being used to deanonymize Tor Browser users.

Both Mozilla engineers and Tor Project members found out about this zero-day after an anonymous user posted the exploit code on a Tor Project mailing list from a Sigaint.org email address.

"This is an Javascript exploit actively used against TorBrowser NOW," the anonymous user wrote. "It consists of one HTML and one CSS file, both pasted below and also de-obscured."

"The exact functionality is unknown but it's getting access to 'VirtualAlloc' in 'kernel32.dll' and goes from there. Please fix ASAP," the user using the nickname FirstWatch also wrote.

In less than an hour after FirstWatch posted this information online, Roger Dingledine, one of the Tor Project leaders, had alerted the Mozilla Security Team, which started working on a fix.

"The Firefox team was sent a copy of [the exploit] this morning," said Daniel Veditz, a member of the Mozilla Security Team. "We've found the bug being used and are working on a patch."

Dingledine says that after Mozilla releases its patch, "then the step after that is a quick Tor Browser update."

Exploit gathers user info and sends it to an online server

While initially it wasn't known what the exploit code accomplished, security researcher TheWack0lian and Trail of Bits CEO Dan Guido have shed some light on its technical details.

The exploit code is a combination of HTML, CSS, and JavaScript code. When hosted on a website and accessed through Firefox or Tor, the exploit code would construct an SVG file that would trigger a UAF (use-after-free) vulnerability that exploits Firefox's SVG parser to leak details about the user's computer and connection.

This data would be sent to a remote server. The collected data included the user's IP address, MAC address, and hostname.

When it was discovered, this data was being sent to a server located at 5.39.27.226 on port 80, which is down at the time of writing.

"Garden variety" exploit with devastating consequences for Tor users

"First off, it's a garden variety use-after-free, not a heap overflow, and it affects the SVG parser Firefox," Dan Guido wrote on Twitter. "This is not an advanced exploit. If you want to see one of those, check out Pegasus which had to deal with code signing and JIT pages."

"As far as exploit techniques, this is a routine UAF that heap sprays a controlled object to kick off a ROP chain. Pwn2Own 2012-level tech," Guido said. "The controlled object eventually gives them RW access to memory, then its game over."

"This type of exploit is much harder to write in Chrome and Edge due to memory partitioning, an exploit mitigation that Firefox lacks," Guido also added.

Guido also says the exploit isn't related to any Metasploit Framework modules, and that the "version regex in the exploit matches Firefox 49, and the specific user-agent that the Tor Browser Bundle uses."

"The vulnerability is present on macOS," Guido adds, "but the exploit does not include support for targeting any operating system but Windows."

TheWack0lian has traced back the shellcode used in this latest exploit to one deployed with a Tor exploit in 2013, used by the FBI in investigating people suspected of crimes on the Dark Web.

Tor Browser users are irreversibly tied to the security features provided by Firefox. If they want to keep Tor Browser up and running, then they should consider donating to Mozilla, who is currently showing a donation form on the Firefox Start Page.
