
	   


Hints of a connection between the defunct GandCrab and the Sodinokibi ransomware get stronger as researchers find code-level similarities and artifacts suggesting continued operations.

At the end of May this year, GandCrab operators announced that they had made enough money to quit the ransomware business. Right before their retirement, Sodinokibi, also referred to as REvil, came out strong in mid-April while targeting WebLogic servers by exploiting a critical vulnerability.

Surprisingly, eight hours after deploying Sodinokibi on the compromised hosts, the attackers also dropped GandCrab 5.2, researchers at Cisco Talos noted, and  indicating that the affiliate was playing for both teams.

Code-level connections

In terms of source code similarities, security researchers from SecureWorks today published more signals pointing to a connection between the two file-encrypting malware families.

A beta version of Sodinokibi was uploaded to the VirusTotal scanning service on April 10 and the first stable release with URI-building functionality similar to GandCrab's followed 20 days later.


credit: SecureWorks

Analyzing the early variants of Sodinokibi, they found that both ransomware variants used nearly-identical string decoding functions.


Shared Code between REvil and GandCrab credit: SecureWorks

To further identify if this was indeed identical, the researchers extracted the opcode for the for loop and used it to search for matching samples on VirusTotal.


FOR-loop opcodes in REvil & GandCrab string decoder function; credit: SecureWorks

Looking at 286 unique samples on VirusTotal, SecureWorks noticed that all of them were confirmed to be either GandCrab or Sodinokibi (or its decryptor). No other malware family could be identified to use the same operation code pattern.

Another hint that the two are related in some way is the URL building functionality used for producing the link for the command and control (C2) server. The pattern in the case of Sodinokibi is the same as it was with GandCrab.

"The C2 URLs for both families consist of two URI subpaths followed by a randomly generated resource name and an extension," the researchers explain. The hardcoded values that help build the C2 URL are available below:


credit: SecureWorks

The researchers admit that it is possible for a different threat actor to imitate the pattern; but this would entail reverse-engineering GandCrab, an endeavor of significant effort. A more likely explanation is that the GandCrab code was repurposed in Sodinokibi/REvil.

Embedded strings further hint to GandCrab link

Adding to the hints above are the debug paths found in the beta version of REvil. The string below, created during development, was left in the malware, probably by mistake:

d:\code\csrc\!1\new_a\gcfin\bin\debug\rwenc_exe_x86_debug.pdb

In the path above, 'gcfin' is the name of the project as given by its author and researchers say that "in context with other evidence appears to refer to “GandCrab Final”."

Further evidence supporting this theory is a REvil file decryptor executable that specifies a debug path containing 'gc6,' which could be a reference to GandCrab 6, possibly what REvil was intended to be.

On top of this, the researchers discovered that a stat JSON data structure that REvil uses to send to the C2 server details about the malware and the victim host.

The integer value assigned to the 'ver' key in the stat JSON points to the malware version, which is consistent with the numbering pattern observed in GandCrab 5.2.


"REvil interprets the value as hexadecimal. The REvil Beta sample includes the hard-coded value 1536, which converts to hexadecimal is 0x600 and indicates version 6.00. This version does not align with REvil's incremental numbering pattern as the next release is version 1.00, but it would align with the GandCrab numbering pattern given that the last observed version of GandCrab was 5.2."


Contrasting operator behavior

While the code may have similarities, the ransomware operator's personalities for the two ransomware threats are in stark contrast.

GandCrab authors had a more relaxed attitude, always ready to taunt and joke with researchers regarding their efforts to fight the ransomware.


credit: Marcelo Rivero

Getting chatty with researchers through their malware code was a mark of the GandCrab author(s), as seen in this comment for South Korean security vendor AhnLab.

BleepingComputer and other organizations fighting ransomware got a taste of the boisterous personality of the developer(s) from the first release of the malware, which used the names of the security groups names for their command and control (C2) domains.


credit: Fortinet

Whoever is behind Sodinokibi adopts a business-oriented behavior that does not engage with the infosec community and stays completely silent outside talks for promoting their malware to affiliates.

They also have strong connections with the ransomware world that allowed them quick launching of their ransomware-as-a-service offer. The level of their connections is such that they afford to be selective about who gets a share of the Sodinokibi-generated profits.

While the operators of Sodinokbi and GandCrab remain unknown, the code clearly hints that the same project may have been used in both cases. Several theories seem to explain both similarities in the code and the difference in attitude.

It may be that only the operators moved away from the business but the devs kept going with new affiliates. Another is that GandCrab management sold the business to a different actor; or the developers are the new operators, or that just a part of the group continues the operation.

Regardless of which theory is the right, or partially right, Sodinokibi carries GandCrab's legacy and is generating a ton of money for affiliates, operators and developers.
