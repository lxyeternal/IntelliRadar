The fact sheet's audience is represented by system or network admins and security officers who want to move to DNS over TLS (DoT) and DNS over HTTPS (DoH) DNS encryptions protocols that offer increased security and confidentiality.

Both DoH and DoT are designed to allow DNS resolution over encrypted HTTPS connections instead of using the currently common plain text DNS lookups.

Google and Mozilla are both running DoH trials for their browsers, with Chrome to upgrade to a provider's DoH server if it present on a pre-defined whitelist or to a shortlist of fallback providers (i.e., Cleanbrowsing, Cloudflare, DNS.SB, Google, OpenDNS, Quad9) if not.

By only upgrading the DNS resolution to DoH if the users' current DNS provider is supported, Google believes that the users' DNS resolution experience will stay the same.

Mozilla's DoH experiments have already been met with criticism from network admins and Linux distro maintainers after the decision to enable DoH by default and using Cloudflare's DoH server rather than a user's existing DNS provider.

Senior scalability engineer Kristian Köhntopp said that Mozilla is "about to break DNS" seeing that Cloudflare will be used for DNS resolution over the default server assigned by system administrators, leading to leaking visited website addresses inside corporate environments to Cloudflare.

Peter Hessler, an OpenBSD developer, tweeted at the time that OpenBSD disabled DoH in their Firefox package in the current releases and will also disabled it in future ones since "sending all DNS traffic to Cloudflare by default is not a good idea."

Users who don't want to use the default DoH Cloudflare server in Mozilla Firefox can disable it by going to about://config, void the warranty and set the network.trr.mode flag to 5.

Modern DNS negative side effects for orgs

NCSC says that the increased adoption of new and encrypted DNS transport protocols will make it harder for security professionals to monitor DNS traffic.

While this will prove to be helpful for users who want to prevent third-parties from sniffing their DNS requests, it will also render organizations' "security controls ineffective, expose internal naming or break connectivity" since software will no longer use system-level DNS resolving, with orgs having to rely on third parties for DNS resolving.

"These negative side effects are hard to mitigate at a network level and require mitigation at DNS infrastructure and individual devices," says the NCSC.

"The NCSC recommends organizations to decide on preferred (DNS) resolvers, configure these on devices under administrative control and take note of the benefits provided by modern DNS transport protocols."

For most organizations where DoH and DoT will be adopted this will mean that some or all of these side effects will be observed:

• Ineffective security controls: Organizations relying on the ability to inspect clear text DNS traffic will likely see their visibility decrease over time. Organizations that implement security monitoring or filtering on the provisioned system-level resolvers will find these measures ineffective once applications start using an alternative resolver.• Leaking information and exposing internal resource naming: DNS queries can contain a lot of sensitive information, including websites visited and destinations for e-mail. Many organizations consider resource records for internal systems and network sensitive information. Using third party resolvers might expose this data and lead to information exposure risks.• Breaking connectivity: Organizations that limit the visibility of internal resource naming to internal networks run an additional risk once devices start using third party resolvers. The third-party may not be able to answer queries for internal resource records, if these are not answered by your authoritative name servers on the public internet. This may break connectivity on internal networks, including popular VPN setups.

Mitigation measures for encrypted DNS risks

To mitigate some of these risks stemming from increasing DoH and DoT adoption, system or network administrators and security officers are advised to take matters in their own hands.

To do this they will have to decide which third party DoT or DoH resolver is more trustworthy and set them on all org systems under administrative control to decrease potential security or privacy risks. 

For devices not under their control, admins will either have to accept the limited visibility for DNS queries or mitigate it using network-level mitigation for some apps such as Mozilla's Firefox.

Firefox currently allows network admins to configure signals using a canary domain that alert the browser of a local DNS resolver designed to implement special features that would make the network unsuitable for encrypted DNS.

"To retain DNS monitoring as an effective measure, it is necessary to make changes to your own DNS infrastructure and endpoints," concludes NCSC.

"While centralized DNS monitoring on networks has been feasible up to this point, this centralized approach will continue to decrease in effectiveness over time."

However, "if your organization starts changing your DNS monitoring today, you will not be surprised by the upcoming changes."
