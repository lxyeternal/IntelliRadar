
	   


Threat actors behind a highly-targeted series of cyber attacks spanning from January to April 2019 have been seen employing malicious tools built using freely available components to infect victims with malware designed to harvest credentials.

The campaign was named 'Frankenstein' by Cisco Talos, a name which "refers to the actors' ability to piece together several unrelated components — leveraged four different open-source techniques to build the tools used during the campaign."

• A GitHub project that leverages MSbuild to execute a PowerShell command

As the researchers further discovered, the threat actors made it their mission to avoid detection, checking for running programs such as Process Explorer and if the infected machine was actually a virtual machine environment.

"The threat actors also took additional steps to only respond to GET requests that contained predefined fields, such as a non-existent user-agent string, a session cookie, and a particular directory on the domain. The threat actors also used different types of encryption in order to protect data in transit," says the Cisco Talos report.


Trojanized Word documents

To compromise their victims' computers, the attackers used two attack vectors. The first one is a malicious Word document which would download a remote template designed to run arbitrary code on the infected machine using a Microsoft Office memory corruption vulnerability tracked as CVE-2017-11882 and gain persistence using a scheduled task named WinUpdate.

The second attack vector utilized during the Frankenstein campaign was another trojanized Word document which requires targets to enable macros to launch a Visual Basic script that checks for malware analysis tools and if the malware has landed in a virtual machine, leading to the sample stopping in its tracks.


Anti-analysis VBA script

Another evasion technique employed by the VBS script "was to call WMI and determine the number of cores allocated to the system. If the number of cores was less than two, the script would stop execution and the end user would receive a pop-up message stating 'The File is not compatible with your Microsoft Office Version'."

In the next step, the attackers made use of a signed Microsoft Build Engine (MSBuild) binary to "bypass application whitelisting controls on the host" and to launch an obfuscated XML file which launched a stager that would download another malicious payload.

The stager was also used in the campaign to establish RC4 byte stream encrypted communication channels with the command-and-control (C2) server — the same one used by the sample distributed via the previously described attack vector — which would send back a command that would execute a PowerShell Empire post-exploitation agent with plugin support.


Deobfuscated stager

System info such as the one listed below was collected immediately after the agent got launched on the compromised machine, information which got delivered to the campaign's operators via an AES-CBC-encrypted C2 communication channel:


• Username
• Domain name
• Machine name
• Public IP address
• Checks if the current user has administrative privileges
• Obtains a list of all currently running processes
• Calls WMI to obtain operating system version
• Obtains the security system's SHA256 HMAC


The C2 channel also made it possible for the threat actors "to remotely interact with the agent to upload and download files and to use the various plugins that were compatible with the Empire framework, such as those used to harvest credentials on the victim's machine."

As Cisco Talos' research team concluded, the use of open source and publicly available components for building the tools powering their Frankenstein campaign allowed the threat actors to blend in and avoid standing out so that experts can't attribute their attacks to a particular actor.
