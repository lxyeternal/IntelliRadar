
	   


Google proposed the addition of automatic blocking of high-risk downloads from non-secure websites in future versions of its Chrome web browsers as revealed by a proposal from Google Chrome security engineer Emily Stark in the World Wide Web Consortium (W3C) public mailing list.

This means that users will no longer be able to download executables or archives delivered over an HTTP connection initiated from HTTPS websites because the Chrome web browser will tag them as mixed content and will automatically block them.

According to the Chrome engineer "We want to achieve the right balance between compatibility/user-disruption and security improvements, so we will likely start by treating certain high-risk downloads initiated from secure contexts as active mixed content and block them."

File types to be flagged as mixed content

Stark said that "We're still finalizing our metrics before we can share them publicly, but right now it's looking like it will be feasible to block a set of high-risk filetypes (executables and archives as determined by the Content-Type header or sniffed mime-type)."

Mozilla security lead Daniel Veditz also expressed interest into adding this feature within Firefox, stating that "I would be very happy to push in this direction, limited by the amount of breakage and user-pushback we can expect. Any statistics you can share would be a huge help. Insecure downloads from the secure sites of companies who ought to know better are distressingly common ('but the executables are signed!')."

The Chrome security engineer shared a poll on Twitter to ask her followers if high-risk non-secure downloads should be considered mixed content and blocked by Chrome. Just a small warning though: proceed with caution when voting though, you might not like the options.



The Chrome team has pushed for making web browsing a safer experience for users for a while now, adding tab-under redirect blocking, blacklisting Adobe Flash and adding HTML5 support as the default option, as well as preventing third-party applications from injecting code and deprecating TLS 1.0 and 1.1.

More recently, a proposal made in 2013 by Google's Mike West to automatically block drive-by downloads originating from website iframes was picked up and got a public design during late January 2019.

Additionally, Google also revealed that they're planning to also add automated blocking of all downloads initiated from ad frames which lack user activation, as part of its larger effort to boost the security of Chrome users by preventing possibly malicious drive-by-downloads.

BleepingComputer has reached out to Google for more details regarding the addition of an automated blocking for high-risk non-secure downloads but did not receive an answer prior to publication.
