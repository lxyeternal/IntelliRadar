
	   


Details have emerged about a new side-channel attack that targets an operating system's page cache, where sensitive data that has been accessed for use, like program binaries, libraries, and files and info sensitive in nature, is stored.

The attack is not limited by hardware architecture and it proved successful in local attempts against Windows and Linux machines, allowing bypassing of security sandboxes, running a timed user interface redressing, and the recovery of temporary passwords generated automatically.

The research team, comprised of experts from Graz University of Technology, Boston University, NetApp, CrowdStrike, and Intel, was also able, under certain conditions, to exfiltrate information to a remote attacker.

One method operating systems (OS) use to improve performance is to store data it reads from the hard disk for the first time in unused portions of the volatile memory. By storing, or caching, the data in memory, when that same data is accessed again it allows the OS to read it much quicker because volatile storage offers access speeds tens of times faster.

Although the researchers demonstrated their attack on Windows and Linux, as page caching is present on all major operating systems it should be possible to obtain the same effect on macOS.

The OS works with virtual memory, where processes are isolated from one another. When multiple processes map a virtual page to the same physical one, it becomes shared memory.

To extract the page cache information, an attacker needs to know when a specific page becomes available in the page cache. This is possible using the system calls 'mincore' on Linux and QueryWorkingSetEx on Windows.


attack overview

Local attacks

Running this side-channel attack locally does not rely on timing differences, something that is necessary for its remote variant.

The prerequisite for a successful local attack is that the adversary has read access to the target page. This condition is fulfilled using a malicious process on the operating system or when processes run in sandboxes that have shared files.

To prove their theory, the researchers performed multiple attacks, one of them with the purpose of sending data covertly.

"The covert channel works by accessing or not accessing specific pages. We use two pages to transmit a ‘READY’ signal and one page to transmit an ‘ACK’ signal. The remaining pages up to the end of the file are used as data transmission bits."

In another test, an authentication UI redress attack was tested. The end goal was to find out when a certain window opened and cover it with a fake clone that even advanced users could not recognize.

A third experiment was a keystroke timing attack on the authentication window of Ubuntu 18.04, to collect the root password.

The test showed partial success with an "extremely" fast-typing user, as false positives occurred. By running the attack multiple times, though, different information can be collected and combined to obtain the complete password.

The experiment was repeated in a text editor (Notepad) on Windows and in both cases the results were clean, with no noise to make more difficult reading the password.


Password capture on Linux (top) and Windows (bottom)

Remote attack possible, with limitations

"Our remote attack leverages timing differences between memory and disk access, measured on a remote system, as a proxy for the required local information," explain the researchers.

This can be achieved by measuring soft page faults - which happens when the page is erroneously mapped, with the help of a process that runs on a remote server.

The researchers were able to send data over a covert communication channel between an unprivileged, malicious process and a remote process acting as a web server.



Since a remote adversary cannot use local functions to verify the presence of a page in the cache, a different approach was used: distinguishing cache hits and misses over the network. The method allows reading over the network arbitrary data from the memory and it was disclosed in the research for the NetSpecter attack.

They ran the experiment on systems with multiple storage types, including solid-state drive (SSD), where timing differences are smaller. However, they amplified the timing difference by using larger files, which helped distinguish between a page cache hit and a page cache miss.

Protection against page cache attacks

The researchers say that their attack is "much more efficient" on Windows than on Linux, but security teams of both operating systems have been informed of the attack.

For the time being, mitigation against this type of attack exists in Windows Insider build 18305, one of the researchers told The Register.

Linux users are in a similar situation. Linus Torvalds published the code for a fix that needs to go through the testing stages before it reaches the end user. On Linux, the issue is tracked as CVE-2019-5489.

The experts involved in the research are  Daniel Gruss, Erik Kraft, Trishita Tiwari, Michael Schwarz, Ari Trachtenberg, Jason Hennessey, Alex Ionescu, and Anders Fogh. Their findings are described in the paper called Page Cache Attacks.

The paper is distributed through the ArXiv e-print service from Cornell University, which stores research articles in various fields of activity (physics, mathematics, computer science, quantitative biology, quantitative finance, statistics, electrical engineering and systems science, and economics.)
