
	   


Exclusive: Researchers from SafeBreach have developed an open source library that creates a fileless file system residing in operating system resources such as the Windows Registry, WMI, or the user defaults system in macOS. This system was created to illustrate how a fileless file system framework could be created to help security software properly detect them.

In order to evade detection from security software, attackers have started to move away from storing their files on disk and started utilizing fileless malware that are loaded directly into memory. In order to stay persistent over reboots attackers will be required to write some files to disk or store PowerShell commands to download and reinstall malware. This, though, increases the chances of being detected

As research into creating a persistent fileless file system that is not easily detected, security researcher Dor Azouri from SafeBreach has released an open source python library called AltFS and released it on GitHub. This library allows researchers to create a file system that resides solely in operating system resources such as Windows Registry, WMI, or the user defaults system in macOS.

Each block of data in a chain contains the ID of the next block, which allows the AltFS library to recreate the stored data.

An example of a superblock and two file chains can be seen in the image below.


Superblock with 2 chains of data

To create an AltFS file system, you can load the library and then create a new instance of the file system while specifying the storage provider you wish to use. A previously stated, available providers at this time are RegistryStorageProvider (Windows registry file system) , UserDefaultsStorageProvider (macOS user defaults system file ysstem), and WMIStorageProvider (WMI file system). 


Example code to create an AltFS File System and store data

SafeBreach has also created a template for researchers to create their own storage providers using other OS resources. Itzik Kotler, the CTO & Co-Founder of SafeBreach, has told BleepingComputer that they welcome contributions from the security community who they hope will contribute further storage providers.

"It’s meant to be public and completely open-source, to allow red teams and other professional to demonstrate it and verify defense tools using it. Everyone is encouraged to contribute more StorageProvider implementations, to support more kinds of artifacts."

In the example provided to BleepingComputer by SafeBreach, the storage provider was created in the Windows Registry. When a file is stored in AltFS, it will be broken up into multiple blocks of data that are stored in the registry as a REG_BINARY value.


AltFS Block in the Registry

You can see how this binary data is displayed in the registry from the image below.


Stored Binary Data

When BleepingComputer asked SafeBreach if they have tested whether their AltFS file system can be detected by security software, they had stated that they plan on testing this in the future. Their focus at this time time is to demonstrate a fileless framework for researchers to play with and contribute to in order to improve it.
