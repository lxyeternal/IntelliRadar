The latest incarnation of the malware has been dubbed AZORult++ because it is written in C++; it does not build on the feature set of the original variant and is less potent at the moment.

However, the presence of code with paths to debugging files suggests that it is under development.

AZORult++ activates remote desktop connection

An analysis from Kaspersky Lab reveals that the C++ version of the info-stealer does not execute on systems where the language is Russian, Armenian, Azerbaijani, Belarusian, Georgian, Kazakh, Tajik, Turkmen, or Uzbek.

One capability the researchers observed in the newly minted successor is setting up a remote connection to the infected desktop.

It can do it by creating an account on the compromised system with a username and password predefined in the malware code. The fresh account is then added to the Administrators group.



To keep the new user hidden, the malware changes to 0 (zero) the registry value of the 'Software\Microsoft\Windows NT\CurrentVersion\Winlogon\SpecialAccounts\Userlist' key. Altering registry key values is also used to enable the Remote Desktop Protocol (RDP) connection on the system.

"The malicious cherry on the cake is a call to ShellExecuteW() to open a port to establish a remote connection to the desktop," details Kaspersky Lab's Alexander Eremin.

This is the last step before the infected machine can accept incoming RDP connections from the attacker.

Malware under construction

Many of the features specific to AZORult 3.3 are present in the new variant, like the algorithm for interacting with the command and control (C2) server, the command format, the way it stores collected data, and the encryption keys.

In contrast, "there is no loader functionality and no support for stealing saved passwords from many of the browsers supported by AZORult 3.3," explains Eremin.

Another clue suggesting a work in progress is a coding mistake that prevents the info stealer from processing correctly the commands from the C2. This means that the malware piece cannot execute certain actions.

The researcher believes that further development will remove glitches in AZORult++ and its functionality will likely increase.
