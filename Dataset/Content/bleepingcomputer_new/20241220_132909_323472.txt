
	   


Docker announced that its native Docker Desktop Windows application will soon switch to the Windows Subsystem for Linux 2 (WSL 2) from the Windows-native Hyper-V virtualization it currently uses.

WSL is a Microsoft-designed compatibility layer that made it possible for users of Windows 10 and Windows Server 2019 to run Linux binaries in ELF format natively on their computers.

However, starting with its second installment, WSL2 uses a genuine open-source kernel compiled from the stable 4.19 version release of Linux at Kernel.org, making it no longer necessary to use a translation layer between apps and their normal system calls.

Besides the move to a real Linux kernel running inside a VM, the switch was prompted by the increased performance with "the time to start a WSL 2 distribution and the Docker daemon after a cold start is blazingly fast – within 2s on our development laptops, compared to tens of seconds in the current version of Docker Desktop."

In addition, WSL 2 can use dynamic memory allocation and access all host CPUs, making it simpler for the Docker Desktop app to manage its resource consumption while also making intensive tasks such as container building a lot faster.

Another bonus of migrating away from the Hyper-V virtualization Docker Desktop uses now is the removal of the Samba Windows service requirement known to cause a lot of headaches to users and admins in enterprise environments.

Windows file bind mounts will work reliably out of the box with the new WSL 2-powered Docker Desktop, with Samba being "deactivated, blocked by enterprise GPOs, blocked by 3rd party firewalls" no longer being an issue.



The WSL 2 integration package "will provide the same features as the current Docker Desktop VM: Kubernetes 1-click setup, automatic updates, transparent HTTP proxy configuration, access to the daemon from Windows, transparent bind mounts of Windows files, and more."

The new Docker Desktop will also make it possible for developers working on Linux Docker daemons on a Windows machine to use the same set of tools they would use on a Linux machine with roughly the same I/O performance as on a native Linux box.

"Combined with Visual Studio Code 'Remote to WSL', Docker Desktop Linux workspaces will make it possible to run a full Linux toolchain for building containers on your local machine, from your IDE running on Windows," also said Ferquel.

The Docker Desktop for WSL 2 technical previews available in July will be able to run side by side with older Hyper-V-based versions, which will make it possible for users of Windows Insider builds to compare performance and feature sets easier.

"In the coming months, we will add more features until the WSL 2 architecture is used in Docker Desktop for everyone running a compatible version of Windows," concluded Ferquel.
