
	   


Google announced that context-aware access capabilities are now generally available for all Cloud Identity-Aware Proxy (IAP) enterprise customers, allowing them to secure RDP and SSH access to cloud virtual machines (VMs).

The feature was initially released in beta during October 2018 and it was expanded to protecting TCP services such as SSH and RDP in January 2019, effectively allowing Google Cloud Platform (GCP) administrators to enable access to internal resources without having to expose the services to the Internet.

This allows access within private corporate networks without the need of setting up bastion hosts which provide access to instances without external IP addresses or of providing public IP addresses to the VMs.

Context-aware access

This allows Cloud IAP customers to "manage access to their web apps hosted on Google Cloud Platform based on context (location, device security status) in addition to their identity."

"Customers trust us with their data, so keeping it secure is our number one goal," says Karan Gupta, SVP, Application Framework.

"Context-aware access in combination with Palo Alto Networks endpoint protection enables us to control access to our infrastructure deployed in GCP following zero trust principles, helping to secure our public cloud workloads while making our work easier and keeping our costs low."


When a user runs SSH from the gCloud command tool, SSH traffic is tunneled over a TLS connection to Cloud IAP, which applies any relevant context-aware access policies. If access is allowed, the tunneled SSH traffic is transparently forwarded to the VM instance. SSH encryption happens end-to-end from gCloud to the target VM--Cloud IAP does not terminate the SSH connection; it only forwards traffic as permitted by the access policies. Remote Desktop Protocol (RDP) works similarly. As an administrator, all you have to do is configure access to the VM instances from the Cloud IAP IP subnet; your VM instances don’t need public IP addresses or dedicated bastion hosts. - Google


Configuring and enforcing granular access policies to the enterprises' internal resources without having to also configure public-facing hosts helps businesses boost their security posture while at the same time providing employees with simpler access without the need of using VPN connections.

"With the general availability of context-aware access in Cloud IAP for SSH and RDP, you can now control access to VMs based on a user’s identity and context (e.g. device security status, location, etc)," adds Google.


Turning on GCP IAP for SSH and TCP resouces

VMs configured by GCP admins with Cloud IAP protection don't need any extra configuration, the only required action being to turn on the feature within the GCP Security tab.

Immediately after, the resource will be secured with the help of a "planet-scale load balancer, complete with DDoS protection, TLS termination, and context-aware access controls."

"Controlling SSH and RDP access to VMs with Cloud IAP brings context-aware access to your backend systems," concludes Google.

The company provides a documentation website to help admins get started, as well as a guide on how to set up internet connectivity for private virtual machines.
