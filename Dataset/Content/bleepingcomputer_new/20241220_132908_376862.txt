
	   


The Tor Project proposed some defense schemes that could be used in the future to limit the impact of distributed-denial-of-service (DDoS) attacks that have been plaguing defend dark web (Onion) sites for years [1, 2].

These defense options would maintain both usability and security after they are applied, making it possible for servers hosting onion services to no longer crash when they are hit by a denial-of-service (DoS) attack.

Inner workings of DoS attacks on Onion sites

DoS attacks targeting Onion sites (also known as introduction flooding DoS attacks) are designed to exploit the onion service rendezvous protocol by sending small messages to prompt the onion services to expend lots of resources to react to the request.

"The attacks exploit the inherent asymmetric nature of the onion service rendezvous protocol, and that makes it a hard problem to defend against," Tor Project Core Developer George Kadianakis said.

"This asymmetry opens the protocol to DoS attacks, and the anonymous nature of our network makes it extremely challenging to filter the good clients from the bad."

This issue cannot be resolved with a simple code change or tweak, but it would instead require fundamental changes to Tor's codebase to fully address it.

However, the Tor Project has been discussing solutions to improve the availability of onion services during DoS attacks for a while now, with a number of them being proposed over a year ago (including the ones presented by Kadianakis):

• Introducing application-layer anonymous tokens that allow legit clients to get priority over DoS attacker.
• PoW approaches like argon2.
• CAPTCHA approaches like introducing a token server giving reCAPTCHA tokens.
• Hiding introduction points by rate-limiting how quickly clients can find them.
• Having intros check that clients don't use the same IP over and over. 
• Pay bitcoin to introduce.

Proposed solutions for the DoS problem

The options suggested by Kadianakis could provide "long-term defense to the problem while maintaining the usability and security of onion services."

One of the ways to make sure that attackers' requests are not prioritized over good clients' ones is to implement an anonymous token system by setting up a CAPTCHA server that would hinder malicious clients' ability to crash onion service servers.

Such tokens (which would be the equivalent of credentials) could also be used in the future to "restrict malicious usage of Tor exit nodes by spam and automated tools," to "register human-memorable names for onion services," and to "acquire private bridges and exit nodes for additional security."

Tor could also adopt a Proof-Of-Work (POW) system (a proposal for one is already available here) to solve the current DoS problem by making it virtually impossible for an attacker to crash an onion service "while still making it reachable by normal clients with only a small delay."

"The great benefit of this approach is that the proposed PoW system is dynamic and automatically adapts its difficulty based on the volume of malicious activity that is hitting the service," Kadianakis explained.

"Hence, when there is a big attack wave the difficulty increases, but it also scales down automatically when the wave has passed."


Image: The Tor Project

As Kadianakis explains, although both these options come with some drawbacks and limitations, they are complementary and they can be applied together.

"Nobody wants a Tor network full of CAPTCHAs or mobile-prohibiting PoW puzzles," he added.

"Parameter tuning and careful design is vital here. After all, DoS-resilience is a game of economics: the goal is not to be perfect; the goal is to raise the bar enough so that the attacker's financial cost of maintaining an attack is higher than the gain."

Last month, the Cybersecurity and Infrastructure Security Agency (CISA) issued guidance on how to protect against cyberattacks originating from or routed through Tor's anonymity network.
