
	   


HP patched a vulnerability discovered in the HP Touchpoint Analytics software installed by default on most HP computers running Windows, a flaw allowing attackers to escalate privileges and execute arbitrary code using SYSTEM privileges.

HP TouchPoint Analytics is a software that comes pre-installed on most HP computers in the form of a Windows service running with top-level 'NT AUTHORITY\SYSTEM' permissions and designed to collect hardware performance diagnostic info anonymously.

The local privilege escalation (LPE) vulnerability tracked as CVE-2019-6333 was found in the Open Hardware Monitor library used by HP's monitoring software.

DLL search-order hijacking flaws like this are is commonly exploited during the later stage of malicious attacks after the targeted machines have already been infiltrated, making it possible to elevate permissions to gain persistence and further compromise the now compromised system.

"HP TouchPoint Analytics ships as a default monitoring component of most HP Windows laptops and desktops," says SafeBreach. "HP patched the vulnerability but SafeBreach researchers believe that any machine using the Open Hardware Library was at risk."

Arbitrary unsigned DLL loading

The vulnerability discovered by SafeBreach Labs security researcher Peleg Hadar and reported to HP on July 4 impacts all versions of HP Touchpoint Analytics Client below 4.1.4.2827.

Hadar says that the security issue is caused by the lack of safe DLL loading caused by using an uncontrolled search path and by not validating if the DLLs it loads are signed with digital certificates.

The researcher discovered that the HP Touchpoint Analytics service — that comes with high-permission-level access to the computer's hardware  — loads a signed Open Hardware Monitor 3rd-party library and three missing DLLs named atiadlxx.dll, atiadlxy.dll, and Nvapi64.dll from folders within the Windows PATH environment variable.

This open source library can be used to monitor temperature sensors, fan speeds, voltages, load and clock speeds of a computer, and "tens of millions of computers use Open Hardware Monitor as part of monitoring systems, including HP Touchpoint Analytics," says SafeBreach.

Next, Hadar observed that the service probed the C:/python27 directory, a folder that comes with an access control list (ACL) providing any authenticated user with write permissions and achieve code execution as NT AUTHORITY\SYSTEM.


Loading unsigned DLLs

This allowed Hadar to escalate the privileges of its own unsigned DLLs after loading them as a regular user, with the end result being that he was able to execute code from within a process digitally signed by HP, a Microsoft-authorized vendor.

"A number of potential attacks could result from exploiting this vulnerability giving attackers the ability to load and execute malicious payloads using a signed service, effectively whitelisting those applications," says SafeBreach.

"This capability for 'Application Whitelisting Bypass' and 'Signature Validation Bypassing' might be abused by an attacker for different purposes such as execution and evasion, to name two."

Further technical details on the discovery process behind the CVE-2019-6333 privilege escalation vulnerability and a disclosure timeline can be found within Peleg Hadar's analysis.

Privilege escalation bug patched

HP patched this vulnerability with the release of HP Touchpoint Analytics Client version 4.1.4.2827 on October 4, following the vulnerability disclosure report sent by Hadar on July 4.


A potential security vulnerability has been identified with certain versions of HP Touchpoint Analytics prior to version 4.1.4.2827. This vulnerability may allow a local attacker with administrative privileges to execute arbitrary code via an HP Touchpoint Analytics system service. - HP


HP published procedures to detect if a device is vulnerable and appropriate remediation actions as part of this security advisory.

“These types of vulnerabilities are alarming because they indicate the ease with which malicious hackers could mount supply-chain attacks targeting and breaching highly trusted elements of our software ecosystem," also added SafeBreach CTO and Co-Founder Itzik Kotler.
