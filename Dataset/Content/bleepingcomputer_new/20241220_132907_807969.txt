Malicious DICOM files can be crafted to contain both CT and MRI scan imaging data and potentially dangerous PE executables, a process which can be used by threat actors to hide malware inside seemingly harmless files.

Cylera's Markel Picado Ortiz achieved this by taking advantage of a DICOM format design flaw which allows for the "128-byte section at the beginning of the file, called the Preamble," to be modified to add compatibility with non-DICOM image viewers.

Hiding multiple streams of data within the same file is definitely not something new (see HERE, HERE, and HERE) but using .dcm files to spread malicious binaries is definitely a novel approach. These types of files are known as "polyglot files" which can contain two streams of data containing different file formats, in our case one is the DICOM imaging file and the other being a Windows .exe binary


PEDICOM file structure

The DICOM files attracted the researcher's attention as the perfect place to hide malicious executables for multiple reasons, from looking inconspicuous to medical staff and that the HIPAA regulations add an extra degree of risk when dealing with them, to the fact that it's the defacto CT and MRI imaging file format used in healthcare for roughly the past 30 years.

As explained by Cylera's researcher, PEDICOM files enable "attackers to effectively turn patient information into malware by embedding fully-functioning executable code into image files used by medical devices such as CT and MRI machines."

Malicious PE/DICOM files can be used by multi-stage malware

However, even though embedding a malicious component into a DICOM is possible as proven by Ortiz, PEDICOM files cannot actually be used to attack healthcare systems on their own, as they cannot be directly executed after being dropped on a healthcare system.

Instead, they have to be dropped as part of a multi-stage malware which would also execute them or they can be used by adversaries who already have accessed to those systems to infect HIPAA-protected data.

As the researcher told BleepingComputer, PEDICOM files even if they would have malware embedded within, "on their own, they do not exploit any vulnerability, that is to say, they need the action of a third party in order for it to be executed."

Ortiz also described how PEDICOM polyglot files can be launched from the command-line, using a custom made batch script, or with the help of another program or malicious tool using the CreateProcess API function.



Therefore, using malicious PEDICOM files would only add to the attackers' already established toolkit a new tool, specifically tailored for healthcare systems where CT and MRI imaging data is omnipresent.



The researcher also detailed three PoCs, with the first showing how to create a PEDICOM file which can be used to display a dialog on the healthcare system where it was dropped after being launched.

The second PoC shows how a potential attacker could further contaminate DICOM files on the system and further spread the infection throughout the network using the third PoC of a hypothetical worm-like attack which spreads over SMB.

Ortiz also underlined the fact that the attempt to spread a potential PEDICOM infection over a healthcare network could come with some difficulties, solutions to this type of issue were found in the past by malicious actors: 


Although to execute commands on remote hosts, it is necessary to have valid active directory credentials, or permissions. In many networks it’s somehow typical to have shared credentials for devices. An example of this approach was used by the Orangeworm Group with the malware named Kwampirs. Still there are more methods to execute commands on remote machines, in example using exploits like Eternal Blue, in the case of Wannacry, but it is not a discussion we want to address in this article. Just to summarize what capabilities someone with bad intentions might use.


Additionally, as shown in Ortiz' research paper named "Attacking Digital Imaging and Communication in Medicine (DICOM) file format standard," there are multiple ways adversaries could use PEDICOM files containing malware as part of cyber attacks against hospitals:


1) Intrusion into hospital infrastructure by hiding malware in DICOM images. Using social engineering through emails to hospital staff.
2) Intrusion into hospital infrastructure by uploading images to the hospital Picture Archiving and Communication System (PACS) using DICOM network protocol.
3) Intrusion into the devices of hospital patients hiding malware in DICOM images. Using social engineering by emailing patients.
4) Keep malware hidden on infected devices, as some antivirus programs do not interpret these images as executable and do not analyze them.


While specially crafted PEDICOM files are not a direct threat to healthcare systems on their own, Cylera's Markel Picado Ortiz revealed in his paper how they can be potent tools for attackers who set their targets on the HIPAA-protected data available on healthcare systems.

When used as part of multi-stage attacks, malicious PEDICOM files can easily be employed to compromise large amounts of sensitive patient data, an infection which is very hard to deal with considering that the compromised files cannot be uploaded to cloud analysis platforms nor it can be shared with third-party cybersecurity companies for further analysis.

Furthermore, antimalware solutions would also have to deal with this type of infection using a specifically crafted process designed to not "compromise patient confidentiality, delete patient information, or disrupt clinical workflows through typical automated response and remediation processes."
