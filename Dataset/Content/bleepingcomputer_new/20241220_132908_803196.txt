
	   


Yesterday, Microsoft migrated to a new Patch Tuesday format, which now lists update information via a portal named the Microsoft Security Update Guide, which for the time being, has managed to confuse most sysadmins.

While the new format conveniently includes a searchable table listing all the updates broken down by KB number, CVE, affected product, or other criteria, most IT and security professionals still miss Microsoft's old format that used Security Bulletins.

The old bulletins were simple to review because they grouped major issues together, listing all KBs users had to install to fix that particular security flaw.

The filters at the top of the table allow IT pros to group updates based on CVEs or patched product, but this is cumbersome, and the new format will get some time to get used to.

Microsoft failed to communicate important security fixes

Microsoft didn't do itself any favors when the April Patch Tuesday announcement didn't even mention of live attacks against some of its patched flaws. Users had to open hundreds of pages to find that information.

For example, Microsoft didn't even acknowledge the zero-day that came to light over the weekend and was obsessively covered by media around the world. This was a serious issue because it was currently exploited to spread Dridex, Godzilla, and Latentbot.

The reason why that vulnerability turned into a zero-day was entirely Microsoft's fault. The zero-day, tracked as CVE-2015-0199, was the result of a bug bounty submission made last October, which Microsoft took six months to patch.

Security researcher Ryan Hanson discovered the flaw, but somewhere in January, somebody else found the same Microsoft Office security hole, but this time around, the ones who found it were malware authors. By the time Microsoft delivered a patch, and following the media attention it got, other malware groups figured out what and how to exploit it.

Two more bugs exploited in live attacks come to light

While the Office zero-day wasn't bad enough, there were two security issues exploited in live attacks, which were also hidden in a mountain of mundane patches.

The second was CVE-2017-0210, an EoP (Elevation of Privileges) vulnerability in Internet Explorer. If admins knew this was an actively-exploited flaw they would prioritize its installation.

Unfortunately, Microsoft didn't let them know, as the only mention was a note of "Exploitation Detected" in a table hidden inside one of the many pages sysadmins had to open to read about IE updates.

The third bug exploited in live attacks wasn't even patched, as Microsoft simply turned off the Encapsulated PostScript (EPS) filter in Office for its customers, which was the point of entry for these attacks.

Microsoft said the vulnerability was tracked as CVE-2017-2605, but the CVE number isn't even assigned. This was no surprise, as the Security Updates Guide portal was rife with bad URLs or mislabeled items.

What are you doing Microsoft?

Microsoft has truly made a mess of this month's security updates, and as Trend Micro's Zero Day Initiative team points out, Microsoft didn't have to make this change in its Patch Tuesday format, to begin with.

Unknown to many was that Microsoft was one of the companies that helped develop ISO 29147, the standard for disclosing security vulnerabilities.

"If there is any irony here, it’s that Microsoft was a significant contributor to the standard, and a security bulletin from 2009 serves as an example for compliance," the Zero Day Initiative team points out. "There remains a question about whether this move will change Microsoft’s compliance with ISO 29147."

Add to this Microsoft's shoddy new portal, the lack of a proper April 2017 Patch Tuesday announcement, the fact that Microsoft didn't even have a Patch Tuesday in February, and that a zero-day discovered last year and disclosed in January was patched in March, and you begin to get an overall look at the sad state of affairs surrounding Microsoft's Security Team in recent months.
