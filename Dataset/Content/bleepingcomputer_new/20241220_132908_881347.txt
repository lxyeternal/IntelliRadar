This issue was first discovered by Vivaldi when they added Windows 10 machines to their browser unit testing cluster, which prior to that was using only Windows 7. When Vivaldi developer Yngve Pettersen was performing the tests he noticed that they took 3 times longer, if not more, on Windows 10 compared to Windows 7.

"We immediately noticed performance problems. A test suite that previously took about 100 minutes to run, now took 300 or even 360 minutes," Pettersen stated in a Vivaldi blog post. "We tried fixing the problem by tweaking the OS configuration, replacing drivers, and adjusting the virtual machine’s configuration. Nothing helped, and we went back to the old Windows 7 Pro instance."

When Pettersen posted the issue to Chrome's bug tracker, Google Chrome developer Bruce Dawson discovered that the issue was related to the Windows 10 exploit protection feature called Control Flow Guard (CFG).

Control Flow Guard is a feature of the Windows 10 Exploit Protection that protects processes from exploits that target memory corruption vulnerabilities such as buffer overflows. This feature is enabled by default in Windows 10 and can be controlled from the Exploit protection settings.


Control Flow Guard (CFG) Settings

According to Dawson, in his tests he discovered that large executables would launch much slower in Windows 10 due to the initialization of Control Flow Guard when using the MiCopyToCfgBitMap function. As the Chromium unit test executable is 122MB, this was causing all the unit tests to run much slower.

"I don’t know what MiCopyToCfgBitMap is doing but it clearly has two nested loops, and can’t efficiently handle large executables."

The good news is that Dawson submitted the bug report to Microsoft on April 15th and a fix was created on April 23rd. This fix is slated to be released in a few weeks.




Timeline to Fix

Should you disable Control Flow Guard?

After reading this, you may be wondering if you should disable Control Flow Guard to increase performance. The answer is no.

Windows 10 is much more secure than previous versions of Windows due to the security features that Microsoft has built into it.  One of these features is Exploit Protection, which prevents your processes from being exploited by a variety of vulnerabilities, even 0-days.

While this performance issue was noticed in the Chromium unit tests, this was because numerous large processes were being repeatedly launched during the tests. For normal every day use, even if your applications contain large executables, they do not repeatedly launch processes where you would notice a performance hit.

Pettersen notes that this issue in CFG could rear its head in web browsers such as Chrome and Vivaldi as they launch new processes for each tab. Pettersen feels this should not be a problem and would not be noticeable in normal use.

"It could be that this issue affects normal browser usage, too, since both Chrome and Vivaldi start new processes for each tab, but as much of the actual code is located in DLLs shared among the processes, and the Windows CFG configuration is reused for DLLs, it might not be as noticeable in normal use."

As the fix for this issue will be released in a few weeks and you have been using Windows 10 with CFG enabled since it was released, it is worth keeping it enabled for a few more weeks in order to stay better protected.
