
	   


A security issue in Check Point's free edition of ZoneAlarm antivirus and firewall solution allowed a user with limited rights on the machine to inject and execute code with the highest privileges.

The glitch could be used in the second stage of an attack and exploiting it requires user interaction. It originated from an insecure implementation of inter-process communications within ZoneAlarm.

Exposed WCF service

Chris Anastasio of Illumant security assessments and compliance company discovered in Check Point's product a .NET application that exposed a Windows Communication Foundation (WCF) service.

The researcher found that SBACipollaSrvHost.exe used WCF and could be leveraged to execute arbitrary code with the highest privileges.



After reviewing the SBACipolla class, Anastasio discovered that Cipolla and CipollaRoot two named-pipe service endpoints are created, which limited the attack to local privilege escalation.

"The service endpoints also have a custom AddSecureWcfBehavior method called on them, an indicator that there may be some attempt by the developers to lock down these services," Illumant notes in a blog post detailing the exploit method.

In this case, the named-pipe server checks if the process initiating the connection has a valid Check Point signature.



Self-signing the exploit code

Because the verification consisted in checking if the program attempting the connection used a valid certificate and that the Common Name (CN) field started with 'Check Point Software Technologies,' the researcher was able to use a self-signed certificate.

The method used by the researcher was described in late 2017 by Matt Graeber of SpecterOps. It allows a low-privilege user to sign code using their own certificate and have Windows trust it.

Windows cannot validate the fake certificate and but does not block the attempt to run the exploit code. Instead, it displays a warning about that and informs the user that deciding to install the certificate leads to Windows trusting all certificates issued by that Certificate Authority.



Most users don't pay attention to these cautionary notifications and allow installation of the certificate. Doing so in the case allowed the researcher to sign the exploit for gaining SYSTEM privileges.

Responsible disclosure

A Check Point representative told BleepingComputer that Illumant followed the responsible disclosure principle, allowing the company to release a patch to ZoneAlarm clients before publishing the details of the flaw.

They said that Anastasio notified them of the "second-grade attack by local exploitation which will allow gaining higher privileges via a bug in one of the ZoneAlarm services on its free product."

"Generally speaking, the industry has around 16000 vulnerabilities per year so this is one of it," the company spokesperson added.

Anastasio is credited for finding the bug on Check Point Products' Acknowledgement page created on January 6.
