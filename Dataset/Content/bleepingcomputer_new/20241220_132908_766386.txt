
	   


Google announced that the Chrome web browser will gradually start blocking HTTPS pages from loading insecure resources to improve the users' privacy and security while browsing the web.

Mixed content is content that gets loaded from both secure HTTPS and insecure HTTP connections which leads to security and user experience degradation on HTTPS websites. Google provides a series of examples of how mixed content weakens HTTPS on its Web Fundamentals platform for developers. 

Google Chrome "we’ll start blocking mixed content (insecure http:// subresources on https:// pages) by default. This change will improve user privacy and security on the web, and present a clearer browser security UX to users," explain Emily Stark and Carlos Joan Rafael Ibarra Lopez of Chrome's security team.

Mixed content affects the browser's security UX

Because web pages are currently allowed to load web assets from a mixed pool of secure and insecure pages, potential attackers could intercept and tamper with some of the insecurely loaded assets to inject malicious code or switch content as they like.

While modern browsers are designed to block some mixed content considered to be a security risk like scripts and iframes by default, some of it such as multimedia content including video, images, and audio will load without any problems, decreasing the users' security on the long run.

"Loading mixed content also leads to a confusing browser security UX, where the page is presented as neither secure nor insecure but somewhere in between," adds the Chrome security team.


Chrome blocking an insecure script (Source: Google)

Mixed content blocking roll-out

The changes leading to the automated blocking of all mixed content in Google Chrome will be rolled out gradually, spread out over multiple releases.

For instance, the Chrome 79 stable release that will arrive in December will be the first to make it possible for users to unblock some blocked content on a per-site basis "by clicking the lock icon on any https:// page and clicking Site Settings."

With the release of Chrome 80 in January 2020, "mixed audio and video resources will be autoupgraded to https://, and Chrome will block them by default if they fail to load over https://," however users will be able to unblock any mixed content assets if they break site functionality.

Chrome 80 will also tag websites as 'Not Secure' using an omnibox chip if they load image content using insecure connections in the hop of motivating site admins to secure their image storage servers.


Unblock mixed content loads via Site Settings (Source: Google)

"Developers can use the upgrade-insecure-requests or block-all-mixed-content Content Security Policy directives to avoid this warning," adds Google's Chrome security team.

In February 2020, when Chrome 81 will be released, Google will autoupgrade all mixed images to HTTPS, with the web browser to automatically block all of those that will fail to load over https://.

More privacy and security-focused changes

In related news, with the release of Chrome 77 on September 11, the browser no longer shows the company name in the omnibar for websites that use extended validation (EV) TLS/SSL certificates, with company names having been moved to the page info bubble which appears when clicking on the lock icon.

Also during September, Google added a new experimental flag titled "Enable improved cookie controls UI" in a Chrome Canary build, a flag that adds a new "Block third-party cookies" option to the "Cookies and Site data" settings when enabled.

This came right after Mozilla released Firefox 69, a release that has third-party tracking cookie blocking enabled by default as part of the Enhanced Tracking Protection feature.

Last but not least, Google's Chrome security team advises web developers to migrate any mixed content served on their websites using the following tips and guides:


Use Content Security Policy and Lighthouse’s mixed content audit to discover and fix mixed content on your site.
	See this guide for general advice on migrating servers to HTTPS.
	Check with your CDN, web host, or content management system to see if they have special tools for debugging mixed content. For example, Cloudflare offers a tool to rewrite mixed content to https://, and WordPress plugins are available as well.
