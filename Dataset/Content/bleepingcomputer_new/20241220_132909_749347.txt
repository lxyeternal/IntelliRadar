
	   


Hackers have been using fake error logs to store ASCII characters disguised as hexadecimal values that decode to a malicious payload designed to prepare the ground for script-based attacks.

The trick is part of a longer chain with intermediary PowerShell commands that ultimately delivers a script for reconnaissance purposes.

Reading between the lines

MSP threat detection provider Huntress Labs discovered an attack scenario where a threat actor with persistence on a target machine tried to run an unusual trick to carry on with their attack routine.

From this position, they used a file called “a.chk” that imitates a Windows erro log for an application. The last column shows what seem to be hexadecimal values.



These are decimal representations of ASCII characters, though. Once decoded, they make a script that contacts the command and control server for the next step in the attack.

A cursory look at the mock log file will likely not raise any flags as the data includes timestamps and references for Windows internal version number, says in a report today John Ferrell, VP of ThreatOps at Huntress Labs.


“At first glance, it looks like a log for some application. It has timestamps and includes references to OS 6.2, the internal version number for Windows 8 and Window Server 2012” - John Ferrell


A closer inspection reveals the trick used by the actor to extract the relevant chunk of data (the numerical characters) and build the encoded payload. Below you can see how the numbers convert to text to form the script.



Ferrell explains that the payload is obtained using a scheduled task impersonating a legitimate one on the host (just one letter makes the difference) and sharing its description. Two executables are involves, both being renamed copies of legitimate files to appear innocuous.

Using legitimate file names

One is named “BfeOnService.exe” and is a copy of “mshta.exe,” a utility that executes Microsoft HTML Applications (HTA) that has been abused for deploying malicious HTA files. In this case, it executes a VBScript to start PowerShell and run a command in it.

The other has the name engine.exe” and is a copy of “powershell.exe.” Its purpose is to extract the ASCII numbers in the fake log and convert them to obtain the payload. Here's how they work:



Ferrell notes that the script decoded this way applies an in-memory patch to the Antimalware Scan Interface (AMSI) to bypass it. AMSI helps antivirus programs detect script-based attacks.

A second command acting as a downloader is executed to retrieve yet another PowerShell command with the same function. At the end of the chain is a payload that gathers information about the compromised system.

It is unclear what the attacker is after, but the last script collects details about installed browsers, general and specific tax-preparation and security products (Lacerte, ProSeries, Kaspersky, Comodo, Defender), and point-of-sale software.

While this is far from being a sophisticated attack, it shows that cybercriminals will explore all avenues to gain a foothold on a target network and develop their attack in creative ways that are likely to pay off in some cases.
