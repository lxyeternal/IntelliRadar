
	   


Researchers discovered a malware loader specifically designed by its developers to hide in plain sight and allow the payload to evade detection by anti-malware solutions by injecting into the memory of compromised computers.

The malicious loader uses "the infamous 'Heaven's Gate' technique — a trick that allows 32-bit malware running on 64-bit systems to hide API calls by switching to a 64-bit environment," as described by Cisco Talos' Holger Unterbrink and Edmund Brumaghin. 

Malware developers add antivirus evasion features to their "products" to lengthen the period of time between their initial release and the moment anti-malware solutions detect them.

This shows just how easy it is for cybercriminals to quickly add advanced techniques like Heaven's Gate to their toolkit by using custom created malware loaders specifically created for boosting the infection capabilities of otherwise easy to detect malicious campaigns.


RegAsm injection

As the Cisco Talos researchers found out, the malware payload is hidden within the packed and obfuscated loader which will unpack it and inject it a legitimate RegAsm.exe process using the process-hollowing.

RegAsm.exe will be created by the malware loader in a suspended state and, subsequently, its memory will be unmapped and replaced with the malicious payload. This means that the payload is never written to the compromised machine's disk making it that much harder for anti-malware software to detect it.

"This type of attack technique cannot be easily mitigated with preventive controls since it is based on the abuse of operating system design features," as per MITRE ATT&CK. "For example, mitigating specific API calls will likely have unintended side effects, such as preventing legitimate software (i.e., security products) from operating properly."

"Besides the aforementioned obfuscation techniques, some API calls are additionally obfuscated by using direct syscalls via the sysenter instruction on 32-bit systems and the Heaven's Gate technique on x64 systems," also add the researchers.

This translates into the malicious code being capable of shifting between 32- and 64-bit systems causing some debuggers and antivirus software to completely "missing these calls as far as they are not expecting a 32-bit application running under the Microsoft WOW64 technology on a 64-bit system to use 64-bit calls directly."


Switch from 32-bit to 64-bit code

The campaign disseminating this advanced loader uses malspam emails as a distribution channel, emails which would commonly abuse the CVE-2017-11882 Microsoft Office memory corruption remote code execution vulnerability impacting the Microsoft Equation Editor.

For this purpose, Microsoft Word documents and Microsoft Excel spreadsheets are attached to the malicious emails camouflaged as invoices, banking statements, and other related documents which will download the loader from attacker-controlled servers after being opened.

The campaign is still active as Cisco Talos further details, with malicious emails and new infected binaries being added to the attackers' malware hosting servers on a daily basis.

Using loaders hardened against detection an capable of deploying any malware strain to compromised machines allows campaign operators to quickly switch between payloads that will also avoid discovery by being injected straight into the infected machine's memory.

A deep dive into how the malware loader uses the Heaven's Gate technique to hide from anti-malware software and a full list of Indicators of Compromise (IOCs) are available in the Cisco Talos blog post.
