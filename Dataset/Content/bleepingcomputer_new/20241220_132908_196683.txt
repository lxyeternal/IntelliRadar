Documentation for Splunk Enterprise warns that a patch needs to be applied before January 1, 2020, for the platform to recognize timestamps for events with a two-digit year.

Splunk software platform helps organizations search, analyze, and view large pools of data from various components of the IT infrastructure or business. It can ingest information from various sources (sensors, applications, devices) and turn it into actionable reports that allow identifying patterns or predicting trends. It can also calculate metrics or create alerts triggered by certain actions.

Different types of dates and timestamps in Splunk are determined by the input processor based on 'datetime.xml' - a file that uses regular expressions to extract the information from incoming data.

The issue is that the unpatched version of the file can extract two-digit years up to 2019, so it will work properly only until the last day of the year.

Come 2020, outdated Splunk instances "will mistakenly treat incoming data as having an invalid timestamp year, and could either add timestamps using the current year, or misinterpret the date incorrectly and add a timestamp with the misinterpreted date."

The documentation adds that on unpatched Splunk instances, incorrect parsing of timestamp data will occur starting from September 13, 2020 at 12:26:39 PM Coordinated Universal Time (UTC). These instances will no longer be able to recognize timestamps from events based on Unix time.

Affected Splunk instances

To avoid the mess, admins should patch the following Splunk solutions in their care, regardless of the underlying operating system:

Splunk Cloud
	Splunk Light
	Splunk Enterprise indexers
	Splunk Enterprise heavy forwarders
	Splunk Enterprise search heads (if data input is from an API or if they forward internal data to other Splunk Enterprise indexers)
	Splunk universal forwarders, under the following conditions:
	When they process structured data such as comma-separated values (CSV) files, with the INDEXED_EXTRACTIONS setting in 'props.conf'
		When they process data inputs prior to forwarding, with the 'force_local_processing = true' setting in 'props.conf'
	
Get an updated 'datetime.xml'

The update is automatic for Splunk Cloud customers and the update will occur at a time provided by the support representative. This operation is critical and cannot be postponed.

For cases where forwarders from on-premise instances send data to the cloud, there are three options to choose from:

Apply an updated 'datetime.xml' to each Splunk instance
	Modify the existing 'datetime.xml' manually by replacing some strings
	Upgrade Splunk to a version that has an updated 'datetime.xml'
Patching the file manually or overwriting the old 'datetime.xml' file with the latest one are the recommended alternatives for environments where an update to a newer version of the Splunk platform is not possible immediately.

Applying the new file should be done after stopping Splunk. The operation should be completed by overwriting the old variant stored in '$SPLUNK_HOME/etc' using the operating system's management utilities. Complete patching instructions are available in the Splunk documentation.
