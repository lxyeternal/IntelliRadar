macOS hacker Patrick Wardle shared the details about how an application trusted by default can be modified to include a synthetic click and allow a malicious event without the user knowing anything about it.

This is the second zero-day issue disclosed in a little over a week that affects macOS Mojave. On May 25 BleepingComputer reported a flaw discovered by Filippo Cavallarin, which allows bypassing Gatekeeper with unsigned code residing on a network share.

Synthetic clicks are automated mouse events application developers can include in their apps to reduce user interaction with security prompts. Wardle has shown before how this feature could be used for malicious purposes and bypass security alerts.

That was for macOS Sierra, though. High risk of abuse prompted Apple to disable this automation in Mojave, prompting the user for explicit consent on a synthetic event.

The current model should prevent attackers from using synthetic clicks to gain access to sensitive components of the OS such as the microphone, location, camera, kernel, messages, scripts, the terminal, or the macOS settings.

Wardle demonstrated that the new protection mechanism is "100% fully broken" as it is possible to modify an app trusted to generate synthetic clicks and thus use it for malicious action.



Legacy apps with privileges

As discovered by Howard Oakley, macOS comes with a list of called 'AllowApplications.plist' with rules that "appear to grant access to protected functions for specific versions of apps, with specific signatures."

The file is part of the Transparency Consent and Control (TCC) system introduced in Mojave to control cross-application data requests.

Among the privileged apps on the list are Steam (before 1.6), VLC (before 3.1), versions of the games Blizzard Heroes of the Storm, Diablo 3, Starcraft, Starcraft 2, World of Warcraft, and specific versions of other software.

Wardle found that Apple's verification of these apps is limited to validating the signature and fails to check the resources it loads and the executable code.



An application under the 'AllowApplications.plist' that is modified to load an arbitrary resource still passes validation, the researcher found. Combined with a synthetic click, this can lead to a full compromise of a macOS machine.

Wardle tested his finding with the pre-approved version of VLC player. He added an arbitrary plugin file to the app's folder making sure that the file matched the pattern supported by VLC.

As a result, VLC is validated by the TCC system despite the modification, and the untrusted code inherited the permission to generate a synthetic click to allow a malicious action.

The severity of such an attack is dampened by the fact that a hacker needs local access to the target system. Once in, the adversary can increase their grip of the system and take full control of it.

Wardle shared the details over the weekend during the Objective by the Sea conference (held in Monte Carlo, Monaco) that focuses on security issues in Apple's operating system.
