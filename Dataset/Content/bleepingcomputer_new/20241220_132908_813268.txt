
	   


Microsoft announced the addition of an Azure Active Directory (AD) sign-in history feature that would allow users to get an overview of past sign-ins and quickly detect any unusual login activity.

Having a simple overview of all login attempts enables Azure AD users to discover potential password-based attacks easier and take action to limit any harmful effects a potential account compromise might have. 

The Azure AD account sign-in recent activity can be accessed via the My Sign-Ins tile, that can be loaded from each user's Overview blade.

Once My Sign-Ins page is loaded, users will be able to get information on:


• if anyone is trying to guess their password.
• if an attacker successfully signed in to the account from a strange location.
• what apps the attacker tried to access.


Successful and unsuccessful sign-ins

The account's recent login activity makes it possible to quickly have an overview of all successful and unsuccessful sign-ins, as well as additional info (OS, browser, approximate location, IP address, and application) needed to understand if unauthorized parties gained access to your account.

Unusual account activity can easily be detected if you spot a strange OS, web browser, or location being used for one of the sign-in events, which could hint that a potential attacker has accessed your account.

"In this case, the user should change their password immediately and then go to the Security info page to update their security settings," says Microsoft Identity Security and Protection team Senior Program Manager Robyn Hicock.

Unsuccessful logins could also be a sign that an attacker has gained access to your Azure AD account. In this case, an "additional verification failed, invalid code" session activity message would mean that the attacker guessed the account password but was stopped by an MFA challenge. 

If no session activity message is displayed for the unsuccessful login event, it either means that you mistyped your password while logging in or that an attacker was attempting to guess it to compromise the account.


Unsuccessful sign-ins (Image: Microsoft)

In this case, Hicock recommends users "to register for Azure Multi-Factor Authentication (MFA), so even if the hacker eventually guesses the password, it won’t be enough to access the account."

"Based on our studies, accounts protected by MFA are 99.9 percent less likely to be compromised," Hicock also adds.

Azure AD customers that want to take advantage of this new capability to check their sign histories for hints of potential ongoing password-based attacks should also be aware that false-positives are a possibility.

This could happen given that the user location is approximated using IP Address geolocation. "For example, if a user signs in on their phone from Washington, the location might show the sign-in coming from California," states Hicock.

This is the exact reason why the recent activity information on the My Sign-Ins page also lists additional information such as the web browser used to login, the user's operating system, as well as the app used during the login process.

Users can also filter the sign-in activity displayed in the My Sign-Ins page with the help of the top search bar based on state, country, browser, operating system, app, or account info.  


Sign-in activity filtering (Image: Microsoft)

More Azure AD security enhancements

Microsoft also announced this month that 16 new Azure Active Directory (Azure AD) lower-privileged roles are now available in preview to help admins boost security by decreasing the total number of Global administrators, as well as to further enhance Azure and Microsoft 365 granular delegation capabilities.

In August, Azure AD Identity Protection detection algorithms' accuracy has been increased by 100% to boost compromised account detection capabilities, while the false-positive rate decreased by roughly 30%.

Redmond also made the Azure AD Password Protection feature generally available in April thus making it possible to block commonly used and compromised passwords to dramatically reduce password spray attack risks.

Azure AD now also comes with built-in support for FIDO2 security keys providing users with passwordless authentication capabilities, as well as allowing them to use passwords with a maximum of 256 characters like the on-premises Windows Active Directory services.
