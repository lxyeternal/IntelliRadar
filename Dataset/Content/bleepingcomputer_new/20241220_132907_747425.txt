
	   


MyBB has released updates today that fix vulnerabilities version 1.8.20 and older that could allow an attacker to take complete control over a site and potentially the server.

Researchers from RIPS Technologies discovered a Stored XSS and File Write vulnerability that when chained together lead to a remote code execution vulnerability in the popular MyBB forum. 

"An attacker merely needs a user account on a target forum to send an admin a private message containing malicious JavaScript code, which exploits the RCE vulnerability," RIPS security researcher Simon Scannell explain in a blog post. "This leads to a full remote take over of a target board by an attacker, as soon as as an administrator who is at the same time authenticated in the backend context opens the malicious PM. No further user interaction is required."

In order to successfully take over a site, the attacker would have to chain a Stored XSS vulnerability and a File Write vulnerability in the admin panel. By chaining them together they can create a PHP backdoor that gives them full access to the site.

The Stored XSS vulnerability is caused by how the forum software converts BBCode to HTML. When converting BBCode to HTML, the parser will go through a 3-step process as shown and explained below.

The process begins by simply escaping all HTML tags and double quotes. It will then convert all [video] mycodes into iframe tags that embed videos from e.g. YouTube. The reason for video bbcodes being rendered in a single step is because they can be disabled by administrators (they are enabled by default). Finally, it will convert all other mycodes, such as [url], [quote] and [email] into HTML markup. 


BBCode Parser

Due to the way the Video BBCode is parsed, it allowes an attacker to nest an URL BBCode inside the Video BBCode and corrupt the resuling HTML. This would lead to an iframe that automatically executes the onload JavaScript event handler when the page loads.



So for example, with this code, a private message could be sent to an admin that automatically executes JavaScript when message is read.

This XSS vuln by itself, though, is not enough to take over the site. That is where the file write vulnerability comes in.

The researchers also discovered that admins could create new CSS stylesheets and save them to the server under any name. This got the researchers thinking they could use the XSS vuln to upload a PHP shell in order to gain access to the server.

The only problem is that the extension for the saved stylesheet file had to end with .css.

On digging further, RIPS discovered that the MyBB database field that held the name of the stylesheet file was configured as a varchar(30). This means that the length of the filename could be no larger than 30 characters and any submitted name larger than that we be truncated at the 30 character mark.


Database Structure

This allowed the researchers to create a file named aaaaaaaaaaaaaaaaaaaaaaaaaa.php.css that was 34 characters long, knowing that it would be truncated to aaaaaaaaaaaaaaaaaaaaaaaaaa.php.

Chaining them together

Now that we have a XSS vulnerability that can execute JavaScript and a vulnerability that can write any file to the server, the researchers could now upload a PHP backdoor by attacking an administrative user of the site.

To do this they send a private message containing the XSS exploit to an administrator. This exploit will execute JavaScript that uses the File Write admin panel vulnerability to create a PHP shell on the server.

If an administrator opens the message while logged into the admin panel, the code will cause the backdoor to be created and an attacker will now have full access to the server.

Security patches released by MyBB

RIPS Technologies reported this vulnerability to MyBB on April 29th, 2019, and MyBB released version 1.8.21 of the forum software on June 10th that fixes these vulnerabilities.

Any site that utilizes MyBB should immediately download the latest version of the forum software and upgrade to the new version.

As these vulnerabilities have now been disclosed, not upgrading will allow attackers to gain full control of not only your site, but also potentially the server.
