An attacker taking advantage of this weakness could allow authentication on a malicious server with no password and at the start of the session send the text PuTTY shows when prompting for the private key passphrase.

To avoid falling for the visual trick, the victim would have to know for sure that the prompt should not appear.

The problem is with the user interface and fixing it proved to be a challenge because the UNIX terminal model offers the server remarkable control over what is shown.

"For example, it wouldn't be enough for PuTTY to display a separator line between the real authentication prompts and the start of the main session, because the server could immediately send escape sequences that moved the cursor back up by a line and erased the separator! If you looked away from the screen and didn't catch the (probable) rapid flicker, you might easily miss that completely, and then the separator line would have been useless."

The solution chosen by the maintainer in GUI PuTTY was to display a small icon of the program, "because it is multicolored and distinctive," the explanation reads.

The maintainer calls this a 'trust sigil' and it appears on any line of the terminal with data legitimately generated by the local  PuTTY during the SSH connection setup.



In Plink command-line connection tool, the fix was to print an interactive message before the start of the main session.

The message prompts the user for action and reads: "Access granted. Press Return to begin session."

At this point, the malicious server has to wait for the user to hit the 'Return' key to be able to overwrite the message. The prompt is "rather annoying," the developers says, so it would be difficult to miss.



EU-funded bug bounty program pays off

Five of the vulnerabilities PuTTY 0.71 addresses were found through the bug bounty program funded by the European Union, which set the reward ceiling to €90,000 for responsibly disclosed bugs in the 20-year old SSH client.

One of the most serious bugs was a  DSA signature check bypass. An attacker could use a fixed signature that would pass the verification.

Fortunately, this vulnerability was present only in development code, so no release version could be exploited with it.

However, PuTTY 0.71 fixes a serious integer overflow bug present in all previous versions of the client. The flaw was triggered by the implementation of the RSA key exchange, which failed to enforce a minimum key length in the process.

"In particular, the server could send an RSA key so short that when PuTTY computed the number of bits (KLEN) in the secret integer K it will encrypt with that key, the number of bits would come out negative. This led to an integer overflow and uncontrolled overwriting of memory."

Another major vulnerability reported through the EU-sponsored reward program refers to hijacking the help file (.CHM format) in the Windows variant of PuTTY. The malicious file could contain dangerous code that would be executed by the SSH client through its 'htmlhelp.exe.'

The list of security fixes also includes multiple denial-of-service attacks that could be activated by writing to the terminal.
