
	   


Keybase received two separate reports for security issues in its app for Linux and macOS that led to privilege escalation on the system. For each of them, the developer paid a bounty of $5,000.

Both reports came via the HackerOne bug bounty platform, the first one submitted by Adam Chester on August 21 for the Keybase Desktop app for macOS.

Helper process allows elevated privileges on macOS

Chester provided a detailed description of the vulnerability and proof-of-concept code that reproduced it. The flaw affected the Keybase Helper process which failed to do proper permission checks in app versions before 2.5.2.

It runs with elevated privileges (root) so it can remove or move files, create folders, add applications and kexts (kernel extensions, the equivalent of drivers) as well as start them.

Chester discovered that any user, regardless of their permissions level on the system, can interact with the Helper process using the MPXPCClient in the MPMessagePack framework.

"Malicious software (outside of Keybase) running on the local computer could have used such a bug to escalate privileges," reads the Keybase security advisory.

The initial bounty for this discovery was $2,500 but the reward doubled after an internal discussion on the quality of the research.

Keybase fixed the issue in September but delayed the public disclosure to allow users to upgrade to a newer version of the app. This month, old versions of the app no longer work, forcing users that have not updated to move to a new revision.

Running any file with root permission on Linux

Keybase received on October 23 another submission for the same type of bug from Rich Mirch, this time exploitable in the Linux version of the app.

An attacker could have leveraged the security gap to increase their privilege level on the system via the keybase-redirector package, used to support multiple local users and separate access to their personal Keybase space.

On Linux, the redirector has root privileges so it can create the mountpoints for multiple Keybase user directories. Users are presented with a symlink by using FUSE (Filesystem in Userspace) interface for userspace programs.

An advisory from Keybase explains that an "attack was possible due to a previous version of keybase-redirector that used the fusermount binary to create the /keybase mountpoint."

The function used to call fusermount, however, did not specify an absolute path to the binary and executed any file named 'fusermount'. A malicious application, for instance, could have changed the $PATH environment variable to a location that included malware, which would be executed with root permissions.

Mirch received a $5,000 reward for disclosing the vulnerability (CVE-2018-18629) and the detailed report on it. Keybase moved quickly and fixed the issue on the same day with the submission.

Public disclosure was delayed in order to allow several release cycles to emerge so users could update to the newer versions.
