
Nexus Repository Manager (NXRM) has new supported REST API endpoints that can automate your binary management needs. REST APIs allow clients to interact with an application, providing them with the capabilities of retrieving and transforming application data. NXRM endpoints make it possible to automate and seamlessly integrate with your tools and CI/CD pipeline.
Create a Blobstore
1st. Create a blobstore. This is the blobstore that we will be associating with our new repo.


	{
	"path": "/dir1",
	"name": "FileSystemBlobStore"
	}
	

Curl:


	curl -X POST "http://localhost:8081/service/rest/beta/blobstores/file" -H "accept: application/json" -H "Content-Type: application/json" -d "{ \"path\": \"/dir1\", \"name\": \"FileSystemBlobStore\"}"

Create a Repository
2nd. We will need to create our repository and we will be using Groovy to accomplish this.
i) Create JSON file mavenScript.json. Here we are creating a script called “mavenRepo” which will create a hosted repository titled “ny-maven-internal”:
{



 "name": "mavenRepo",



 "type": "groovy",



 "content": "repository.createMavenHosted('ny-maven-internal')"



}

Post Script to NXRM
ii) Post this as a script to NXRM:


	curl -u admin:admin123 -X POST --header 'Content-Type: application/json' \
	http://localhost:8081/service/rest/v1/script \
	-d @mavenRepo.json

Run the Script on NXRM
iii) Run this script on NXRM to create the repo:


	curl -vvv -u admin:admin123 -X POST --header 'Content-Type: text/plain' \
	http://localhost:8081/service/rest/v1/script/mavenRepo/run

Create a Role
3rd. We need to create a role so that this can later be assigned to our new user. This role grants read and write permissions on repo ny-maven-internal.


	{
	"id": "ny-dev-role",
	"name": "ny-dev-role",
	"description": "New York dev team role",
	"privileges": [
	"nx-repository-view-maven2-maven-internal-add",
	"nx-repository-view-maven2-maven-internal-browse",
	"nx-repository-view-maven2-maven-internal-read"
	]
	}

Curl:


	curl -X POST "http://localhost:8081/service/rest/beta/security/roles" -H "accept: application/json" -H "Content-Type: application/json" -d "{ \"id\": \"ny-dev-role1\", \"name\": \"ny-dev-role\", \"description\": \"New York dev team role\", \"privileges\": [ \"nx-repository-view-maven2-maven-internal-add\", \"nx-repository-view-maven2-maven-internal-browse\", \"nx-repository-view-maven2-maven-internal-read\" ]}"

Create a User
4th. Create User. In this step we will assign this user the ny-dev-role we created in step 1.


	{
	"userId": "dmedley",
	"firstName": "Dory",
	"lastName": "Medley",
	"emailAddress": "dm@email.com",
	"password": "password",
	"status": "active",
	"roles": [
	"ny-dev-role"
	]
	}

Curl:


	curl -X POST "http://localhost:8081/service/rest/beta/security/users" -H "accept: application/json" -H "Content-Type: application/json" -d "{ \"userId\": \"dmedley\", \"firstName\": \"Dory\", \"lastName\": \"Medley\", \"emailAddress\": \"dm@email.com\", \"password\": \"password\", \"status\": \"active\", \"roles\": [ \"ny-dev-role\" ]}"

That’s it! In four steps you have created a user that has read/write access to their team’s new repository.
