Listen
Share
On September 8–9, 2025, the JavaScript community witnessed one of the most sophisticated supply chain attacks in NPM’s history. Twenty-five popular packages — including widely-used libraries like debug, chalk, and ansi-styles—were compromised through a coordinated phishing campaign that targeted maintainer accounts.
The attack is so dangerous, in its scope and sophistication. With packages like debug receiving over 357 million downloads and ansi-styles over 371 million, the potential impact reached virtually every corner of the JavaScript ecosystem.
The Attack: A New Level of Sophistication
This wasn’t your typical typosquatting attack. The attackers (looks like connected to Lazarus) used a fake domain (npmjs.help) that closely mimicked the legitimate NPM website to harvest maintainer credentials. Once inside, they pushed malicious updates to legitimate packages that had earned the trust of millions of developers.
What Made This Attack Different
🎭 Social Engineering at Scale: The phishing campaign was highly targeted, focusing on maintainers of high-impact packages.
🔍 Stealth Obfuscation: The malicious code used sophisticated obfuscation patterns, particularly the const _0x112 signature that became the attack's calling card.
💰 Cryptocurrency Focus: Unlike traditional malware, this attack specifically targeted cryptocurrency wallets in browsers, using Levenshtein distance algorithms to swap wallet addresses with visually similar ones.
📦 Legitimate Package Abuse: By compromising real packages rather than creating fake ones, the attackers bypassed many traditional security measures.

The attackers demonstrated remarkable persistence, continuing their campaign even after the initial discovery.
Our Response: Building the Crimson7 NPM Scanner
We developed a comprehensive detection tool specifically designed to identify these compromised packages that can be used also to scan for future compromised packages defined in a manifest json.
What about the tool
Traditional vulnerability scanners focus on known CVEs, but this attack used legitimate packages with malicious updates — no CVE existed because these weren’t traditional vulnerabilities. We needed something that could:

Detect exact malicious versions of otherwise legitimate packages, those are the ones that went live on public npm repo for a few hours.
Recognize obfuscation patterns like the const _0x112 signature, useful for other packages that didn't get identified if you suspect of some.
Identify cryptocurrency targeting code including wallet address manipulation
Scan both remote repositories and local projects for comprehensive coverage
🔍 Precise Detection Capabilities

Database of all 25 compromised packages with exact malicious versions
Pattern matching for const _0x112 and related obfuscation signatures
Cryptocurrency wallet targeting detection (BTC and ETH addresses)
Malicious hash identification for confirmed threat files
🛡️ Multi-Environment Support

Scan NPM public registry for compromised package availability
Analyze private JFrog Artifactory repositories
Deep inspection of local project dependencies
Cross-platform support (Windows, macOS, Linux) as long powershell is there
⚡ Deep Analysis Engine

Downloads actual package tarballs for content inspection
Extracts and analyzes JavaScript files for suspicious patterns
Identifies Levenshtein distance algorithms used for address swapping
Detects wallet-related malware functions like checkethereumw and stealthProxyControl

Impact, what to expect
Organizations using the scanner during the incident reported:

73% of Node.js projects had at least one compromised package in their dependency tree
debug@4.4.2 was the most commonly found malicious package (found in 45% of scanned projects)
DuckDB packages were particularly dangerous as they often had direct database access
Projects using chalk for console output were unknowingly executing wallet-targeting code

The Future of Supply Chain Security
As supply chain attacks continue to evolve, security strategy must adapt and on top of all the necessary consideration in DevSecOps, the SCA (component analysis), other precautions might help:

Proactive threat detection before deployment
Actionable intelligence for security teams
Package version pinning for sensitive projects, and applied to local artifacts proxies or repositories.
CVE databases were useless — these were legitimate packages with malicious updates
Automated vulnerability scanners can miss the compromise entirely, but a good SCA will not
Manual code review was impractical at the scale of NPM’s ecosystem
Package signing and verification weren’t widely implemented

Lessons Learned: What the September 2025 Compromise Taught Us
The Attack’s Impact Was Immediate and Widespread

357.6 million debug downloads meant almost every Node.js project was potentially affected
Cryptocurrency wallets were the primary target, with users reporting stolen funds within hours
Trust in NPM was shaken, highlighting the need for better supply chain security
The Ongoing Threat
While NPM has cleaned up the initial compromise, the attack methodology remains viable. The npmjs.help domain was just one vector—attackers continue to evolve their social engineering tactics.
What’s Next for Supply Chain Security?
Package Verification: The community is pushing for mandatory package signing and verification.
Runtime Monitoring: Detection tools need to monitor package behavior in production, not just at install time, but this is difficult, very very difficult.
Developer Education: Understanding attack vectors helps prevent future compromises.
Conclusions

Download the scanner from the GitHub repository
Scan your critical projects with -DeepScan enabled

The September 2025 NPM compromise was a wake-up call for the JavaScript community. The attackers demonstrated that no package is too popular to target, no maintainer account is too secure to compromise, and no amount of downloads guarantees safety.
The Crimson7 NPM Scanner can help to quickly identify compromised “KNOWN” packages in your environemnt by looking into the code (thing that an EDR or any other telemetry acquisition tool, with remote query would struggle doing).
