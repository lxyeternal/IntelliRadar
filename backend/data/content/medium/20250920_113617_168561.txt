What happened?
Yesterday (September 8th, 2025), attackers hijacked an npm maintainer’s account and published malicious versions of popular packages including chalk, debug, ansi-styles, supports-color, strip-ansi, and more.
The injected code runs in the browser, hooking fetch and XMLHttpRequest to replace wallet addresses with those controlled by the attacker.

Quick detection
Install ripgrep and search for known IoCs:
ripgrep is a line-oriented search tool that recursively searches the current directory for a regex pattern.
Deep detection
Step 1 — Check effective versions
Step 2 — Pin safe versions
Add only the affected ones you discovered. Identify safe versions by looking up advisories / changelogs online (npmjs.com, GitHub issues, security advisories).
🔎 Add entries only for the packages that showed up in your lockfile as compromised. If a package never appears, don’t pin it.
Step 3— Reinstall cleanly
You usually don’t need to delete package-lock.json / yarn.lock / pnpm-lock.yaml. Only remove a lockfile if, after adding overrides/resolutions and reinstalling, the resolver still keeps the compromised version.
Important note about lockfiles
- If your lockfile already pins a safe version: ✅ don’t delete it.
- If it pins a compromised version: 🚨 add overrides/resolutions and regenerate.
- If you’re unsure: 🔄 reinstall clean to make sure node_modules matches the lockfile.
Step 4— Rebuild & validate

Rebuild your app.
Run ripgrep again to ensure IoCs (_0x112fa8, etc.) are gone.
If you published bundles, redeploy clean builds and invalidate caches/CDNs.
Conclusion
This incident shows how quickly a single compromised maintainer can poison the ecosystem. Check your lockfiles now, pin safe versions only if you’re affected, rebuild, and add stronger supply-chain defenses.
